# 通しの筋書き（runtime の確かめ）

機械が読む正本は `harness/runtime.scenario.json`。この文書は人が読む要約で、命令は JSON の側に 1 か所だけ書く（ここに写さない）。

works-factory は修正の工場で、人は入口の殻 `bin/works-factory` で Archon の命令をそのまま打ち（`workflow run works-factory-line` で依頼を渡して run を始め、`workflow respond` で止まった所で答え、`workflow wait`・`workflow get` で今どこか・報告を見る）、`bin/apply` で封じた差分を当てる。run は、工場が 1 つの依頼を受けてから報告を出すまでの 1 回の実行。工場の工程は、判定・計画・修正・報告などの部品（ブロック。各々が `workflows/<名>/` のフォルダ）を順に並べた線。

ASF（Archon という AI の工程を回す道具の作者が作った、issue から merge までの工程の束）の `archon-lifecycle` は、取り込む前にこの筋書きを実際に動かして確かめる。対象は `tests/e2e/make_target.py make` が試みごとに作る小さな種のリポジトリ（`stats.py` の 2 つの欠陥と、それを名指す依頼）。

## `request-to-report`

目的: 種の対象に依頼を 1 つ渡し、本物の役で線を始めから報告まで回す。人の関所では関所の文を見て通す。

期待: 線の run がちょうど 1 つ起き、終わりの記録の状態が `completed`、結末の語が報告の 10 語の 1 つ、報告の本文が空でない。当てる前の対象は作った直後のまま。

**落ちたと言える物:** run が起きない・関所で答えても先へ進まない・結末の語が 10 語の外・報告が空・当てる前に対象が変わっている。殻が認証を拾えずに止まったのは製品の不具合ではなく、判定できない（inconclusive）。

## `every-block-ran`

目的: 線の中の 8 つのブロック（試験の関門・判定・計画・事前審査・修正・独立の目・取り込み・報告）が、通しの中で全部本物に走ったことを run の記録で示す。

期待: 線の include ごとに、その中の節が親の run の記録で 1 つ以上 `completed`（修正の include も親の run で見る）。修正の役そのものは fix の組ごとの子の run の中で走るので、子の run のどれかで修正の役の節が `completed`。独立の目の R1〜R4 の役の節が省かれずに `completed`。

**落ちたと言える物:** どれかの include の節が 1 つも `completed` でない・子の run が無いか、どの子でも修正の役が走っていない・R1〜R4 のどれかが省かれた。

## `capabilities-evidenced`

目的: 今の works の能力の棚卸しの行ごとに、本物の run の記録に跡が在るかを、照らしの表 `tests/e2e/evidence.json` と照らしの道具 `tests/e2e/evidence.py` で機械に照らさせる。

期待: `check` が `absent`（見えるはずの行が見えない）も `unreadable`（記録が読めない）も 0 件で終わる。`unexpected`（まだ見えない扱いの行が見えた）は落ちたとしないが、行を全部書き出す。

**落ちたと言える物:** `absent` か `unreadable` の行が 1 つでも在る。

## `changed-diff-refused`

目的: 封じた後に差分が変わると、`bin/apply` が当てずに止まるかを見る。

期待: 1 バイト変えた差分で `bin/apply` が 0 以外で終わり、封じた hash（差分の指紋）と合わないことを言う。対象には何も当たらない。

**落ちたと言える物:** 変えた差分が当たる・終了の値が 0・対象が変わる。

## `sealed-diff-fixes-seed`

目的: 封じた差分を当てると、種の落ちていた試験が通るかを見る。

期待: 当てる前は依頼が名指した 2 件の試験が落ち、当てた後は 3 件全部が通る。差分は空でなく、変わったファイルは報告が挙げたファイルの中だけ。

**落ちたと言える物:** 差分が空・当てても落ちた試験が通らない・前から通っていた試験が落ちる・報告に無いファイルが変わる。

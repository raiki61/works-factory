How to read the diffs: the review that looked at an item in the earlier pass raised no hole that blocks the fix other than the earlier blocks and owed suggests. In this pass, look only at (1) whether those earlier holes are gone (if gone, put the key in `resolved`; if they remain, raise them again in `faces` with the same key, the same severity, and the same `reach`) and (2) the new holes that the diff and the ripple list make. A diff row is `<mark> <place>: <sentence>`: `-` is a sentence only in the earlier pass, and `+` is a sentence added in this pass (unchanged sentences are not shown). A line `contract fields changed: …` names the contract fields of the item that changed (the whole item is not shown). Do not look again at places outside the diff to search for new holes. Do not change the rule of severity (block or suggest) or the rule of `reach`: if you relabel a block that had a central value to `peripheral`, write in the first sentence of `why` why it no longer meets the earlier definition.

When the material has the section "Overlaps and other items' scope": if the diff of an open item disagrees with the units, the scope, or the files touched of the other items listed there (closed items included), raise that disagreement as a hole too. The other items' plan text is not shown there; read the files in the working tree if you need them.

How to read a ripple list: its uncovered hits are the hits that none of the item's writable paths (`allowed_paths`), acceptance tests (`tests`), or rewritten tests (`rewrite_tests`) cover. Anything the fix will touch (callers to align, tests that assert a literal value to rewrite) must be in that item's `allowed_paths` or `rewrite_tests` now: what is in the plan can be written during the fix without asking about scope, and anything outside it can only be written after the fixer asks the plan role and gets permission. Check every uncovered hit: the item covers it, it has no effect, or it is a hole. When the list says `ripple list missing: …` (the machine could not build it), look up the callers and the tests yourself.

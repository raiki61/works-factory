# 組み込みの決め（issue #765 の組み込みの PR を機械的にするための決めの一覧）

- 何の話か: 古い工場（`workflows/`・`lib/`）を `blocks/` の部品に作り直した後の「組み込み」（古いコードを消し、`blocks/` を `workflows/` に入れ替えて本線を新しい block に切り替える 1 本の PR）で、黙って能力が落ちうる所の棚卸し（4 節の 72 項目）を、1 件ずつ今のコードで確かめて行き先を決めた。
- 分かったこと: 当たり 59・一部当たり 11・外れ 2。外れの 2 つは直す物なし。残りは全部、行き先（block の `src/`・lib に残すモジュール・graph）か、落とす訳を決めた。組み込みの PR は、各項目の「決め」と「直す文書」をそのまま当てる。
- 持ち主に求めること: 1 つ（下の「持ち主に聞く物」。守りのファイルの一覧 `lib/protected.json` の行の書き換え。行を変えてよいのは人だけ）。

語（初出の物）:

- README: `docs/design/README.md`（部品の作り直しの型。設計の正本）。「README 9.3」はその節。設計書の名だけ書いた物（`fix.md` など）は `docs/design/` の同じ名の設計書。
- keep-essence: README 10 節の、外してはいけない 12 の仕組み。番号は 10 節の番号。
- KEEP／MOVE／DELETE: 組み込みの後も `lib/` に残す／block の `src/` へ移す／消す（README 9 節）。
- 使い手: その名を呼ぶ block・graph（line・chain・judge・eyes）・`bin/`・残る lib のモジュール。使い手が 2 つ以上なら lib、1 つならその block の `src/`（line・chain の `src/` を含む）。lib とほかの block は block の `src/` を import できない。
- 〔確認〕: 棚卸しの指摘がコードで当たったか（当たり・一部当たり・外れ）。
- place: block が自分のファイルを書く run directory の中のフォルダ（README 4.4）。prep: AI の役の直前で指示を組む script の node。埋め: Archon に無い物を補う部品（`workflows/.shared/` の `fence.py` など。組み込みで `.shared` へ移る）。
- 始めの記録: line が run の頭に書く記録（line.md の語）。block は読まず、port の値で受ける。
- r1〜r4: 独立の目の 4 つの block（設計書 `r1.md`〜`r4.md`）。`lib/eyekit.py` は r1 の PR（まだ main に無い）が足す lib のモジュール。

決め方（この順に当てた）: keep-essence の 12 は落とさない → 使い手の数で lib か block の `src/` か → README と 1 枚の設計書が食い違えば、能力を残し、より簡潔な方を採り、直す側の行を「直す文書」に書く → どの決まりでも決まらない物だけ持ち主に聞く。行番号は今の main（このブランチの元）のコード。2 波目の設計書（`fix.md`・`diagnose.md`・`delta-review.md`・`lens.md`・`plan.md`・`plan-review.md`・`r1.md`〜`r4.md`・`verify.md`）はまだ main に無い版の行番号。

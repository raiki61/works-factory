# block の設計書: r3（独立の目 R3 全体の整合）

- 何の話か: 修正の後に、変更全体のファイル横断の整合（命名・規約・界面・文書の追従）と、考えの住処の外に考えを書き足していないかを、直しを作った役と別の会話で見る目 R3 を、単独で呼べる block `workflows/r3/` にする設計。4 つの目の共通の形は [r1.md](r1.md) の 0 節（以下「r1.md の 0.x」）に従う。型は [README.md](README.md)、手本は [world.md](world.md)。
- 決めたこと: 今の eyes の `r3-coherence` と `r3-coherence-verdict` の 2 つの node と、`prep.py`・`lib/eyeverdict.py` の R3 の部分を、5 つの node の block にする。R3 の観点の指示の全部は共通の断片 `eye-coherence` に置き、この block の md と、R3 と R4 を 1 つの会話で見る時の r4 の md（[r4.md](r4.md) の port `coherence`）の 2 つが差し込む。受け付けの輪は今と同じく持たない。README の 8.4 の素描にある port `intent`（書いた意図の文書）は持たない（9 節の 1）。振る舞いは変えない。
- 持ち主に求めること: なし。
- 読む人と使い方: この block を作る実装者（1.3〜5 節の名と順をそのまま作る）と、その PR の審査役（2.3 などの「英語の md が持つべき今の指示」の一覧を 1 つずつ照らす）。急ぎではない（README の 11.1 の 2 波目。r1 の PR の後に作る）。

この文書の語は README の頭と r1.md の頭の物を使う（目・累積差分・判定の行・eyes のまとめ・今・族の部品・例の run）。ほかに:

- 持ち主: このリポジトリの owner（決めを下す人。README の頭の語）。「持ち主の決め `<名>`」は `docs/owner-decisions.md` の同じ名の節。
- line: 工場のメイングラフ（README の頭の語の graph の 1 つ）。run の始めの記録を書き、承認ノード（人が答える node）と深さの表を持ち、block に入力の値を配る。block はほかの block と line を名指さないので、値の出どころは各書の 1.6 にだけ書く。
- Archon: 工場の workflow を回す実行系（README の頭の語）。返答の型（`output_format`）を照らし、落ちた node へ `with:` で結んだ node を誤りで止める。
- 頭の深さの段: run の初めに決める重さの段（軽量・標準・重厚。持ち主の決め `dynamic-depth`）。軽量の run だけ、R3 と R4 を 1 つの会話で見る（持ち主の決め `eyes-by-reason`）。どの段かを決めて目に渡すのは line。
- 段落の印: 指示の md の中で、差し込むかを選ぶ段落を囲む `<!-- if <名> -->`・`<!-- if not <名> -->`・`<!-- end <名> -->`（README の 5.1）。入れ子にできない。
- 決まった文: 指示の md に英語で書く、run によらない文。字の正本は作る block の `prompts/` の md で、設計書は中身の決まりと、守るべき今の指示の一覧（2.3 など）だけを持つ（README の 13 章）。
- keep-essence: 元の works が守る 12 の仕組み（README の 10 節）。9 は「独立設計と R1〜R4」。
- E の番号: 今の目の能力の棚卸し `docs/plans/2026-10-13-capabilities/tail.md` の「E: 独立の目（eyes）の能力の棚卸し」の行の番号（例 E7 は「累積差分は本文を貼らず、ファイルを最後の行まで読み切らせる」）。行き先の一覧は r1.md の 0.12。
- 組み込み: 全部の block がそろった後に、古いサブグラフを消して line を新しい block に切り替える 1 本の PR（README の 11.3）。KEEP・MOVE は README の 9 節の lib の仕分け（KEEP は lib に残す、MOVE は block の `src/` へ写す）。
- 2 つの commit の形: README の 11.4 の指示の比べ（1 つ目の commit で日本語の md が今の指示と同じ字かを照らし、2 つ目で英語にする）。今回の 2 波目は使わない。
- 整合の役（r3-coherence）: 変更全体の整合を見る AI の役（inspector）。道具は Read・Grep・Glob。
- prior-decisions: 素材の観点の block の 1 つ（先行議論の突合。docs/design/prior-decisions.md）。対象の決定記録を洗い、決着済みの論点を `material.json` に返す。その論点は記録された方針の行の出どころの 1 つ。
- 柵の表: 対象のリポジトリに在れば読む、考えの住処の外に考えを書かせない表（`docs/concepts.json`。`lib/conceptfence`）。直した後の実測が、表の在る対象でだけ住処の外の知る場所の増えを数える。
- 記録された方針: 役を縛る決まりの一覧（方針の文書の写し・依頼の answers・承認ノードの人の答え・先行議論の突合が挙げた決着済みの論点と、無人の run が採った推し。`lib/policy.py` の `recorded`）。役が方針とのぶつかりを言う時は、この一覧の行の名指しを字のまま写す。
- 例の run: r1.md と同じ run `df5e111f-ea97-409b-8066-2245d32746ab`。この run は軽量で、R3 は R4 と 1 つの会話（`eyes-one`）で見た。整合の役の指示の骨組みは、その時に機械が書いた R3 の観点の指示書 `eyes/one/r3-coherence.md`（今の `r3-coherence.md` に支度の値を差し込んだ物）から取った。返答は `redesign-needed`（文書の追従の欠け）。

## 1 block の全体

### 1.1 役

累積差分が触れた範囲で、変更した物が既存と揃っているか（命名・規約・界面・文書の追従、変更が触れる文書群が示す推奨の一致）と、差分が考えを住処の外に書き足していないかを見て、見た範囲と見ていない範囲つきで判定の行を返す。差分が触れていない横断のリスクは見ない（R4 が見る）。方針とぶつかる所は、記録された方針の行を名指して reason に書く。

### 1.2 port

入力（YAML の `inputs:`）: r1.md の 0.2 の `base`・`lang`・`green`・`policy`・`after`・`review`・`answers`・`request`・`pushes`・`decisions` の 10 個。`lang` の人に見せる欄は 2.4。`answers`・`request`・`pushes`・`decisions` は記録された方針の行を組むためだけに読む（`eyekit.recorded_rows`）。

出力（`returns: finish`、`outcome_field: ok`）: r1.md の 0.3 の欄だけ（`questions` はいつも `[]`）。

今との違い: 今は eyes の 25 の入力から、prep が始めの記録の差分の根・方針の写し・言語・依頼の answers を、判定の隣から問いの台帳と推し（`gatemarks.ledger_at`・`taken_pushes`）を、`decisions`（決定記録の突合の返答）を読み、直した後の実測の節を eyes の置き場と事前審査の置き場から組んでいた。block は推しを line から値で受け（port `pushes`）、直した後の実測と事前審査の結論を port `after`・`review` で受ける。

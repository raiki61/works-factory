## 2 層と頼り

- 層の地図 `docs/layers.json` の層 `viewer`（`may_use` は `shell`・`lib`）。どの層の `may_use` にも入らない。

- 照らし: 見る道具へ頼らない向きは `tests/layers/test_viewer_apart.py`（E25 の 1）、`lib/` が見る道具を import しない向きは `tests/layers/test_lib_blind.py`（地図から頭のフォルダを作る `scan.LAYER_IMPORT` に `viewer` が入る）。見る道具自身の `may_use` は機械で照らさない: import の照らしは頭のフォルダの単位で、`may_use` の層の頭（`bin`・`lib`）がどれも許されるので照らす字が無い。block と graph の中の物を import しないことは人が見る（YAML と md と script の docstring を字として読むのは作りの読みの役目で、頼りに数えない）。

## 4 作りの読み（`src/shape.py`）

- 根（pack のフォルダ）を引数で受け、今の木 `<clone>/workflows` と run の写し `<写し>/project/.archon/workflows/<pack>` を同じ形で読む。
- ノードの読み分けは種類の鍵（`loop_group`・`include`・`workflow`・`approval`・`wait`・`prompt`・`command`・`loop`・`cancel`・`bash`・`script`）のどれか 1 つ。0 個か 2 個以上は読み分けられない物として `problems` に出す。AI のノードの md（`prompts/<id>.md`）・script のノードの script（`scripts/<名>.py`）が無い物と、工場の名の頭で始まるのに木に無い `include:`・`workflow:` の先も `problems` に出す。工場の名の頭で始まらない `workflow:` の先（Archon 同梱の `archon-pr`）は工場の外の graph として印を付ける。

## 5 記録の読み（`src/runread.py`）

- run の家の `archon-home/archon.db`（名は `isolate.DIRS`）を読むだけで開く。選んだ run は、id・グラフの名・状態・結末（run の行の欄 `outcome`。8 章）・結果の語（一番上の返すノード `result` の最後の `node_completed` の出力の全文の欄 `outcome`。8 章）・止まっている承認ノード（状態が `paused` の run だけ。DB の `node_suspended` の後に終わりの無いノード。繰り返しの中の待ちでは Archon が本体のノード `<器>.<本体>` と器の両方に `node_suspended` を書くので、待つ本体を持つ器は並べず、答えが入れば器も外す。止めた・放棄した run は `node_completed` を書かずに `cancelled` になるので、状態で絞る）・始め・かかった秒・費用を持つ。費用は metadata の `total_cost_usd`。空なら DB のノードの終わりと後から書く費用の出来事〔`node_completed`・`node_failed`・`node_deferred_usage`〕のうち自前の費用の行の `cost_usd` の和で、run 自身の行だけを足す。自前かは Archon の `nodeCostScope`〔`node-record-serialization.ts`〕と同じ: `accounting` が `node` の行で、`accounting` の無い古い行は `aggregate` が true でなければ自前。どの行を足し何を外すか（`compose_fan_out` の instance の終わりの行〔出力の欄 `type` が `compose_fan_out_instance`〕と子の run の扱いを含む）は [archon.md](archon.md) の「使用量（トークンと費用）の数え方」の箇条に従う。費用の欄を持つ行が 1 つも無い run は和を出さず空のまま〔bash だけの run を無料の AI の run に見せない。`dag-executor.ts` の `persistRunUsage`〕。`total_cost_usd` と和の両方が在れば大きい方を出す: Archon は `total_cost_usd` を run の末尾〔待ち・落ち・終わり。`dag-executor.ts` の `persistRunUsage`〕だけで書き、SIGTERM で落とす道〔`packages/cli/src/utils/owned-run-termination.ts` の `failWorkflowRun`〕は書かないので、承認で起き直して走っている run と、その後に SIGTERM で落ちた run の `total_cost_usd` は前の待ちの時の古い値で、費用は減らないので今の和より小さい。答え待ちと終わった run は `total_cost_usd` が正で、和と同じか大きい。
- run の始めとかかった秒は、run の行の始めと終わりでなく、出来事の最初と最後の時刻から出す（子の run を含むログの出来事の始めと終わり）。承認の答えで起き直した run は、Archon が run の行の始めを起き直した時刻に書き換える（`packages/core/src/db/workflow-run-resume.ts`）ので、行の値では答えの後の数分しか出ない。出来事の無い run だけ行の値を使う。選んだ run の始めは、ログの出来事の最初の始めと、DB の出来事の最初（run の始めの印 `workflow_started` を含む）の早い方にする（DB の時刻は秒までの切り捨てなので、同じ秒ならログ。ログだけだと始めの印からノードの始めまでの数秒が抜ける）。終わった run（子の run も）の終わりは、DB の最後の終わりの出来事（`workflow_completed`・`workflow_failed`・`workflow_cancelled`）の時刻と、ログの出来事の最後の終わりの遅い方にする（SIGTERM で落ちた・待ちのまま止めた run はログに終わりを書かないので、ログの出来事だけでは終わりが早すぎる。DB の時刻は秒までの切り捨てなので、DB だけだと最後のノードの終わりより前になりうる）。終わりの無い出来事（待ちと、止めた・落ちた run で走り中のまま止まった AI と機械のノード）は、その run の終わりの出来事のうち、出来事の始めの後の最初の物（始めと同じ秒の物も。DB の時刻は秒までの切り捨て。ただし同じ秒の内で始めの前にログの起き直しの行〔`workflow_resume`・`workflow_start` の 2 つ目から。最初の行は run の始め〕が在れば、その秒の落ちは始めの前〔落ちた後に起き直してから始めた〕として数えない。落ちた後の走り直しの分け〔下の状態の訳〕も同じ。`runread.RESTART_ROWS`）の時刻で閉じ、印 `cut`（true）を付ける（記録で確かめた終わりと見分ける。人の答え待ちの和もそこまで数える。落ちた後に起き直した run は、前の起動の走り中のノードを最後の終わりでなくその落ちで閉じ、状態を落ちにする〔run の最後の終わりの止まり方で言うと、完了した run で人が止めたように読める〕。Archon は起き直す時、終わっていないノード〔走り中・待ち・落ち〕に前の起動の id を使い直す〔`dag-resume-snapshot.ts` の `unfinishedInvocations`〕ので、閉じる終わりは出来事の最後の始め〔`last_start`〕の後の物から選ぶ。落ちは過去の事実なので、落ちた後に起き直してまだ走っている・答えを待っている run でも、前の起動の走り中・待ちのノードはその落ち〔最後の始めの後の最初の `workflow_failed`〕で閉じ、走り中の物を落ちにする。起き直した後に走り直したノードは、前の落ちでは閉じない）。閉じる時刻は始めより前にしない（長さを負にしない）。閉じる時刻は DB の書き方からログの書き方（`YYYY-MM-DDTHH:MM:SS.000Z`）に直して入れる（T も Z も無い DB の書き方は手元の時差で読まれる）。走り中の run は最後の出来事までの長さ。子の run の行も同じく、その子と孫の出来事から出す。DB の時刻は秒までで時差を持たないが UTC（`datetime('now')`）として読み、ログの時刻と比べる。読めない時刻の行（字でない時刻も）は、その時刻を数えずに進み、読めなかった物（`unread`）に数える（組みを落とさない。段の集計には読める時刻か空だけが渡る）。
- run を名指さない時に開く一番新しい run は、出来事の最初の時刻の新しい順（出来事の無い run は行の始め）。行の始めで並べると、起き直した run が後に始めた run より新しくなる。
- 選んだ run の記録は、DB の行の `output_root` から `logs/<run>.jsonl` を読む。子の run は DB の `parent_run_id` と metadata の `parent_node_id` で辿り、子の出来事の道の頭に親のノードの道を足す。run の写しは `<output_root>/workflow-source/runs/<run>/project/.archon/workflows`。写しが無い run は今の木で読む。
- 飛んだノード（`node_skipped`）は、道と飛んだ時刻（`time`）と訳（`cause`）を持つ。起き直した run が前の起動で済んだノードについて書く行（`content` が `prior_success`。`node-event-write.ts`）は飛びに数えない（その道が済んだことは前の起動の出来事で見える。数えると走ったノードが訳無しの飛びに並ぶ）。起き直すたびに Archon は `when`・`trigger_rule` で飛ぶノードの行も新しい起動の id で書き直すので、同じ run・道・周（`loopPath`）の飛びは最初の 1 つだけを持つ。
- 出来事はノードの起動（`execution.invocation.id`）ごとに 1 つ（落ちた後に同じ起動の id で走り直した物は、始めごとに分ける。下の状態の訳）: 始めと終わり（時刻はどれもログの書き方）・run の終わりで閉じたかの印 `cut`（閉じた出来事だけに在る。上の終わりの訳）・状態（走り中・待ち・済み・落ち。繰り返しの器は答えの後に同じ起動の id で `node_start` を書き直すので、待ちから走り中に戻す。起き直す前の落ちで閉じた走り中の出来事は落ち。前の起動で落ちて同じ起動の id で走り直した物は、落ちた起動の出来事を残し、走り直しを新しい出来事にして一度落ちたことを印 `fell` に持つ〔Archon は起き直す時、落ちたノードの前の起動の id と情報を使い直す。`dag-resume-snapshot.ts` の `unfinishedInvocations`。`node_error` の行も費用・トークン・会話を持つ。窓口の決め: 長さ〔段の AI の秒・時間の内訳・時間の帯も〕には走っていた間だけを数えて落ちから起き直しまでを入れず、費用・トークン・往復・会話はどの起動の分も落とさず、会話は両方とも残し、最後が通った所に前の誤りを今の誤りとして出さない。落ちた起動の出来事は状態が落ちで、その時の誤りの字を持つ〕。SIGTERM で落とす道〔`owned-run-termination.ts` の `failWorkflowRun`〕はログに `node_error` を書かず DB に `workflow_failed` だけを書くので、前の始めと次の始めの間にその run の落ちが在る物も同じで、落ちた起動の出来事はその落ちで閉じて印 `cut` を付け、走り中だった物を落ちにする）・落ちた時の誤りの字（`node_error` の `error`）・費用（自前の費用の行だけ。自前かは上の費用と同じ `nodeCostScope` の形。束ねた行は数え直さない）・模型とトークンと往復の数・会話の始まり方（`binding.sessionOrigin`。続けた会話は `resumed`）・道具の呼び出し（`provider_event` の `tool_call` と `tool_call_update` を試み〔`attemptId`〕で結ぶ）・script と bash の出力の終わり（`exec_output`）・出力（DB の `node_completed` の `node_output`。通った起動の出来事だけに付け、同じ起動の id の前の落ちた出来事には付けない。20,000 字で切って載せ、切る前の字の sha1 を `digest` に持つ）と、出力が指す run の置き場の小さなファイル（`archon_artifact` の `run_id` と `path`。絶対パス・`..`・symlink で `artifacts/runs/<run>/` の外を指す物と、NUL の字を持つ物は読まずに `unread` に数える。run の置き場の外は読まない。読みで OSError が出る物〔長すぎる path・読む権限の無いファイルなど〕も、組みを落とさずに `unread` に数える。置き場に無いファイルは数えずに進む）・その run の置き場の根（`artifacts`）。

## 6 会話の記録の読み（`src/session.py`）

- 隔離した Claude Code の設定（`claude-config/projects/`）の中から、記録の `binding.sessionPreview`（会話の id の頭）で会話の記録を探す。Claude Code が消した古い記録は結べない。頭が 2 つ以上の記録に当たれば、黙って選ばずに読めなかった物（run の `unread`）に数える。頭は 16 進の字と `-` だけを通し（Claude Code の会話の id は UUID）、ほかの字（`/`・`..`・glob の字）を持つ頭は置き場の外や別の会話に当たるので、探さずに読めなかった物に数える。
- 続けた会話（出来事の `sessionOrigin` が `resumed`）の記録は、前の会話の往復を元の時刻のまま写して持つ（続けるたびに新しい会話の id の記録を作り、前の記録には書き足さない。ノードの始めの行の `sessionPreview` は前の会話、終わりの行は新しい会話の頭で、出来事は終わりの行の頭を持つ。2026-10-30 の工場の run の記録で人が確かめた。Claude Code の版は止めていない）。その出来事の始めより前の往復に `copied` を付け、トレースの span にしない（写し元の会話と二重になる。8 章）。流れ（`seq`）には残す（LLM に入った物なので）。読めない時刻の往復は時刻を持たず、読めなかった物に数える。
- system と道具の一覧は `api-request-shape`、添え書き（system の片と `<system-reminder>` の片）は `api-request-blob` から取る。この 2 つの型が普通の利用者の Claude Code でも出るかは確かめていない。型の行が在ったかを `recorded` に持つ。
- Claude Code の版は工場が止めていないので、記録の形は試験で照らさない（人が見る）。行の型は、読む型（`session.py` の `READ_TYPES`。指示と道具の結果・返事・system と道具の一覧・添え書き・費用と、往復の始めの時刻だけを読む API の頼みの印 `api-request`）と読まない型（訳つき。`UNREAD_TYPES`。添え物・待ち行列の印・会話の題など、LLM に入った字を別の型から読む物と中身を持たない物）に分ける。どちらでもない知らない型の行と JSON の object でない行と、型の欄 `type` が字でない行と読む型の行の中の欄の形が違う行（`message`・`shape` が object でない・`content` が字でも列でもない〔字は字の片 1 つとして読む。API の形で許される書き方。道具の結果の `content` も同じ〕・字の片に `text` が無いか字でない〔空の列・0 などの偽の値も〕・道具の呼び出しの id や道具の名が字でない・往復のトークンや費用〔`cost-state` の `totalCostUSD`〕が数でないなど。1 行は、書き込む値を全部取り出して形を確かめてから流れ・往復・添え書き・字の束に一度に書くので、途中で止まった行は何も変えない。`runread.SHAPELESS`。組みを落とさない）だけを数えて返し、「読めなかった物」の数に入れる（読まない型まで数えると、数が本当に読めなかった物を指さない）。ただし LLM に入った字を別の型から読む型（`session.py` の `READ_FROM`。読まない `attachment` は `api-request-blob` から、時刻だけを読む `api-request` は `api-request-shape` と `api-request-blob` から字を読む）は、代わりの型が記録に無い会話では知らない型と同じく数える（代わりが無ければ LLM に入った字が黙って消える）。
- 往復の印は、usage を持つ行を待たずに往復（新しい `message.id`）の最初の行で置き、usage は後の行で埋める（usage の無い返事が混じっても往復の数がずれず、どの返事にも usage が無くても返事と道具の呼び出しが消えない）。往復は最初の行の時刻（`at`）を持ち、道具の呼び出しは切る前の入力の字の番号（`text`）を、会話は作業の場所（`cwd`。最初に `cwd` を持つ行の値）を持つ。
- 往復と道具の時刻（トレースの組み。8 章）: 往復は始め `start` と終わり `end` と模型 `model` を持つ。始めは返事の行の `requestRef` が指す `api-request` の行（`id` が同じ物）の時刻で、`api-request` の行が無いか当たらない往復は、その往復の前の最後の `user` の行（道具の結果か指示）の時刻、それも無ければ往復の最初の行の時刻。終わりは同じ `message.id` の最後の行の時刻。2026-11-04 の工場の run の記録で、親の会話と下請けの全部の返事が `requestRef` を持ち、どれも同じ会話の `api-request` に当たった。`api-request` の行は返事の行の並びの次とは限らない（下請けの記録では道具の結果の後の返事の前に `api-request` が無い所が在った）ので、並びでなく `requestRef` で結ぶ。道具の呼び出しは id と始め `at`（`tool_use` の片を持つ行の時刻）と、同じ `tool_use_id` の `tool_result` を持つ `user` の行の時刻 `done`・結果の字の番号 `out`・誤りの印 `error` を持つ。会話は読めた時刻の最初と最後 `span` を持つ。
- 下請けの記録: 会話の記録の隣のフォルダ `<会話の id>/subagents/` の `agent-<id>.jsonl` を同じ読み（`session.read`）で読み、同じ名の `.meta.json` の欄（親の会話の Agent の `tool_use` の id `toolUseId`・説明 `description`・種類 `agentType`・深さ `spawnDepth`・起こし方 `requestShape`）を `meta` に、`agent-` の後の字を `id` に持つ（会話の `agents`）。行は `isSidechain: true` を持つが、読みは親の会話と同じ。meta が無い下請けも読み（親に結べないことはトレースの組みが数える）、JSON として読めないか欄の形が違う meta は読めなかった物に数える。続けた会話の下請けは、親と同じ `since` で写しの往復に `copied` を付ける。

## 6.5 段（`viewer/stages.json`・`src/stages.py`）

- 段は、line（メイングラフ）の一番上のノードを人の言葉で畳んだ単位（受付・判定・計画・修正・報告など 11 個）で、見る道具だけの考え。トレースの段の span（8 章。段の名と、段ごとの集計の欄を属性に）と、run の span の出力の段ごとの費用の表（段ごとの集計の費用）が使う。
- E11 の 3 つの答え: Archon は持たない（Web の画面の run の詳細は、include を開いた平たいノードの図とログの並びで、ノードを段に畳む物と段ごとの時間は無い）。ASF も持たない。要る: ノードの平たい並びからは、どこからどこまでが判定で、どこからが修正か・どの段に何分と幾らかかったかが読めない。
- 表の置き場は見る道具の中。工場の文書の形に見る道具の都合を持ち込まない。行ごとに名・出どころ（`source`。`docs/design/line.md` の 1.3 の番号。表を直す人が読み、部品は読まない）・中のノードの id（`nodes`）と配線の列（`wiring`。下）を持つ。段は run の頭の深さ（軽量・標準・重厚。`docs/design/line.md` の「語」）とは別の考え。
- 出来事の段は、出来事の道の頭（line の一番上のノード）で引く。include・繰り返しの周・子の run の出来事も道の頭は line のノード。run が line の run でなければ段に集めず、出来事に段の番号を付けない（表は line だけ）。段の表に無い line のノードの出来事は段の番号を持たず、トレースでは run の span の直の子になる。
- 段ごとの集計（データの `stages.run`）: 状態（通った・落ちた・待ち・走り中・飛んだ・記録に無い。所〔run・道・周〕ごとの最後の出来事の結果で決める。落ちた後に起き直して完了した run で、前の起動で落ちた所が起き直した後に通った段は通ったにし、一度落ちたことを印 `fell` に残す。同じ起動の id で走り直した所も、読む部品が起動ごとの出来事に分けるので同じ〔走り直しの出来事も印 `fell` を持つ〕。窓口の決め。）・始めと終わり（段の出来事の最初と最後）・人の答え待ちの秒（`wait:` のノードの長さの和）・AI の秒と手番の数（AI のノードの長さの和と数）・往復の数（`turns`。Archon が数える出来事の往復の和）・周の数（`rounds`。繰り返しの本体の場所と周の番号の列 `loop` の組の違う物の数で、入れ子なら内の周まで。本体の場所は道を繰り返しの区切り `.` だけで切った物で、本体に直に在るノードと本体の include の中のノード〔`plan-rounds.design-turn` と `plan-rounds.plan__draft`〕を同じ周に数える〔受付 c31850 の足し 2e1ffb〕。同じ段を何周回ったかで、無駄な回り直しを見る）・費用（ドルの和だけ。4 分けごとのドルは出さない）・4 分けのトークン（記録の `input`・`output`・`cacheRead`・`cacheWrite` の和）。
  - 新しく読んだ分（`uncached`）と cache の内訳が知れない手番の数（`cacheUnknown`）は、工場の共通の口 `lib/runlog.py` の `add_tokens` と同じ訳で出す: `uncached` は `input` から cache の 2 つを引いた物で、cache の欄が欠けた手番（Archon では「知れない」の意味で 0 ではない。`docs/design/archon.md`）と `cachePartial` の手番が 1 つでも在れば出さない。`input` が cache の 2 つの和より小さい手番は引けないので数を `odd` に持ち、1 つでも在れば `uncached` を出さない（包みの関係は Claude Code と Archon の版で変わりうるので決まりとして照らさない）。

## 8 トレースへの組み（`src/trace.py`）

- 何の物か: 選んだ run の記録（5 章の `runread.run`・6 章の会話と下請けの読み・6.5 の段の集計）から、OpenTelemetry のトレース 1 本の span の木を組む。字と数だけの dict の列を返し、網には出ない。持ち主の決め `run-trace-otlp`。
- 木（1 本の run を 1 本のトレースに）:

  ```text
  run（AGENT。名は graph の名。run の id・状態・結末・line の run の結果の語・Archon の総額・段ごとと AI のノードの上位の費用の表）
  └ 段（CHAIN。stages.json の段。line の run だけ。段ごとの集計の欄を属性に持ち、時刻は集計の始めと終わり〔中の出来事の最初と最後〕）
    └ 中の出来事を束ねる器（CHAIN。runread.GROUP_KINDS: 繰り返しの器・並べて起こす器・子の run を起こすノード）
      └ 周（CHAIN。繰り返しの器の中の出来事を、器の 1 つ深い周の番号で分けた物。時刻は中の最初と最後）
        └ ノード（AI のノードは AGENT、script・bash と人の答え待ちは CHAIN）
          ├ 往復（LLM）
          ├ 道具（TOOL）
          │  └ 下請け（AGENT。meta の toolUseId の Agent の道具の下）
          │     ├ 往復（LLM）…
          │     └ 道具（TOOL）…（下請けの中の下請けも同じく、その呼び出しの下）
          └ …
  ```

  - 出来事の親は、その出来事を中に持つ一番内の器の出来事（道が器の道の下で、同じ run なら外の周の番号が器と同じ。繰り返しの器は周を 1 つ深く持つ。子の run の出来事は run が違い、周の番号は子の中だけの物なので比べない）。include で開いた子（道の `__`）は span にせず、ノードの道を属性に持つ。
  - 裏で走る下請け（`requestShape: background`）は親の Agent の道具が数十ミリ秒で返った後も走るので、下請けの span は親の道具の span より後に終わる。OpenTelemetry はこれを許し、組みは時刻を詰めない。
- 結末（run の span の `works_factory.outcome`）: Archon が run の行の欄 `outcome` に書く成否（`succeeded`・`failed`。`runread.OUTCOMES`）。Archon は graph の `returns:` のノードが終わった時に、その出力の `outcome_field:` の欄（boolean）を成否にして書く（止めた Archon の `dag-executor.ts` の `persistAuthoredOutcome`。Archon の命令 `workflow status` が `authored outcome` と出す値と同じ）。結末はその後の run の成り行きに関わらず書くので、返すノードの後に落ちた・止めた run も結末を持ち、起き直した run は書き直されるまで前の値を持つ。返すノードが終わる前に走り中・答え待ち・落ちた・止めた run は欄が空で、印 `none`（`trace.NO_OUTCOME`）を置く（空の値は属性に置かないので、印が無いと「結末を読まなかった」と見分けられない）。
  - これにした訳（受付 20261104-204934）: 候補は run の状態・最後の承認の答え・報告の出口の語（line の返すノード `result` の出力の `outcome`。`lib/report.py` の `OUTCOMES`）の 3 つだった。状態は run の span の `works_factory.status` に既に在る。承認の答えは承認ノードの span の出力に在り、run の結末とは限らない（答えの後に落ちる・止まる run もある）。出口の語は line だけの物で、ほかの graph と子の run には無い。Archon の成否はどの graph にも在り（どの workflow も `returns:` と `outcome_field:` を持つ。`tests/layers/test_block_returns.py`）、Archon が自分で記録する事実で、見る道具が工場の字を読み分けずに済む。line の出口の語は、別の欄の結果の語（下）に置く。
  - 前は run の span の結末がいつも空だった（`runread.run` が結末を返さず、組みが空の値を置かなかった）。
- 結果の語（line の run の span の `works_factory.line_outcome`）: 工場の line が報告に書く結果の語（`fixed`・`no_fix_needed`・`stopped_by_human`・`round_limit` など。語の組の正本は `lib/report.py` の `OUTCOMES` で、`runread.RESULT_WORDS` は写さずにそれを引く）。Phoenix で「人が止めた run」などで絞るため、結末と並べて置く（受付 20261104-235220。持ち主の答え「とりあえず」で窓口の推しの「並べる」）。
  - 読む物: 選んだ run の一番上の返すノード `result`（line の `returns:`。`runread.RESULT_NODE`）の DB の最後の `node_completed` の出力の全文の欄 `outcome`（`runread.RESULT_WORD`）。出力は値でも JSON の字でもよい。ノードの span の `output.value` は 20,000 字で切るので、切った字からは読まない。起き直して `result` を 2 度終えた run は最後の物。
  - 欄を置くのは line の run（6.5 の段の集計が在る run）だけ。line の run で語が無い（`result` が終わる前の run）か、語の組に無い（`result` が報告を受けられず空の語を返した時など）は印 `none`（`trace.NO_OUTCOME`）。line でない run（`result` を返すほかの graph を含む）は欄を持たない。
  - 読む名と line が合うことは試験が縛る（`tests/viewer/test_trace.py`: line の YAML の `returns:` と `result` の `output_format` の欄、語の組が `lib/report.py` の `OUTCOMES` そのものなこと）。
- 段の span の属性（段ごとの集計。6.5）: 状態 `works_factory.status`（`ok`・`failed`・`waiting`・`running`・`skipped`・`none`）・一度落ちた印 `works_factory.fell`・段の秒 `works_factory.seconds`・人の答え待ちの秒 `works_factory.wait_seconds`・AI の秒 `works_factory.ai_seconds`・AI の手番の数 `works_factory.ai_steps`・ノードの数 `works_factory.steps`・往復 `works_factory.turns`・周 `works_factory.rounds`・費用 `works_factory.cost_usd`・トークン `works_factory.tokens.<名>`（`input`・`output`・`cacheRead`・`cacheWrite`、出せる時の `uncached`・`cacheUnknown`、引けない手番の数 `odd`）。始めと終わりは span の時刻にする。段の span は、その段に一番上の出来事が在る時だけ作るので、出来事の無い段（飛んだ・記録に無い）は span を持たない（配線のノードだけが走って飛んだ段は span を持ち、状態が `skipped`）。段の費用は中のノードの費用の和で、ノードの span と二重になるが、Phoenix は `works_factory.cost_usd` を足さない（費用の数えは上の「費用」）。
- 時刻: どれも記録の字のまま（ログの書き方の UTC のミリ秒。Archon のログと会話の記録は同じ機械の時計で、合わせる手間は無い）。run は `runread.run` の始めとかかった秒、ノードは出来事の始めと終わり（終わりの無い出来事は始めの時刻で閉じる）、往復と道具は 6 章の `start`・`end`・`at`・`done`、下請けは下請けの記録の読めた時刻の最初と最後。終わりが始めより前の物は始めにそろえる。
- 属性は Phoenix が読む OpenInference の名に寄せる（`openinference.span.kind`・`llm.model_name`・`llm.provider`・`llm.token_count.*`・`input.value`・`output.value`・`tool.name`・`session.id`）。GenAI の取り決め（`gen_ai.*`）は Development で、Phoenix は OpenInference に変換して読むので採らない。工場の物は `works_factory.*`: ノードの道 `path`・周の番号 `loop`（`.` でつないだ字）・ノードの種類 `kind`・状態 `status`・段 `stage`・Archon の費用 `cost_usd`・Archon が数えた往復 `turns`・4 分けのトークン `tokens.<名>`・道具の結果の切る前の字の数 `result_chars`・下請けの説明と種類と深さと起こし方 `subagent.*`・誤りの字 `error`・読めなかった物 `unread`（run の span に JSON の字で）・結末 `outcome`（run の span）・結果の語 `line_outcome`（line の run の span）・段の集計の欄（段の span。どちらも下）。
- トークンの足し算: Claude Code の会話の記録の `input_tokens` は cache を含まない。OpenInference の `llm.token_count.prompt` は cache を含む全体なので、`input_tokens + cache_read_input_tokens + cache_creation_input_tokens` を入れ、cache の 2 つを `llm.token_count.prompt_details.cache_read`・`cache_write` に、`total` を `prompt + completion` にする。ノードの span の 4 分け（Archon の `input` は cache を含む）は `works_factory.tokens.*` にだけ置き、`llm.token_count.*` に置かない（Phoenix の中の和は子の LLM の span から積み上がるので、ノードに置くと二重になる）。
- 費用: 正は Archon の値（`runread` の `cost`）で、run と段とノードの span の `works_factory.cost_usd` に置く。器と周の span には載せない（中と二重になる。`runread.GROUP_KINDS` と同じ訳）。Phoenix は span に明示した費用を使わず、LLM の span の模型の名とトークンから自分の値段の表で計算し直すので、run の span の出力 `output.value` に Archon の値で段ごと（6.5 の段の集計）と AI のノードの上位 10 の費用の表を書く（Phoenix の値との差と訳は下の「Phoenix で見た事」）。下請けごとの費用は記録に無い（会話の `cost-state` は会話ごと・模型ごとの和で、下請けの分を含む）ので、下請けの span にはトークンだけを置く。
- 中身: 会話と道具の中身は既定で載せる（決め `run-trace-otlp` の 2）。往復の span には、その往復で新しく入った物（前の往復の後の指示と道具の結果）を `input.value` に、返事と考えを `output.value` に置き、文脈の全部は置かない。system と道具の一覧と最初の往復の前の指示は、ノードの span（下請けは下請けの span）の `input.value` に 1 度だけ置く。道具の span は入力と結果。字は 1 欄 20,000 字（`runread.CLIP`）で切り、切った欄は切る前の字の数を `works_factory.chars.input`・`output` に持つ。
- 写しと重なり: 続けた会話の写しの往復（6 章の `copied`）は span にせず、写しの往復の呼び出しに結ぶ下請けも span にしない。2 つ以上の出来事が同じ会話の id の頭を持つ時は、最初の出来事にだけ会話を置き、ほかは読めなかった物に数える（同じ往復を二重に置かない）。
- 読めなかった物: run（5 章）と会話と下請け（6 章）の `unread` に、組みで結べなかった物（親の呼び出しに当たらない下請け・時刻の無い出来事・同じ会話の id の頭）を足して返し、run の span にも置く。黙って落とさない。
- id: 乱数にしない。トレースの id は run の id から、span の id は run の id と所の鍵から sha256 で決める（トレースは 32 字・span は 16 字の 16 進）。所の鍵は、段は番号、出来事（ノードと器）はその出来事の run・道・周・始めの時刻、周は器の鍵と周の番号、往復は親の鍵と往復の番号、道具は呼び出しの id、下請けは呼び出しの鍵と下請けの id。出来事は Archon の起動の id を持たず、落ちた後に同じ起動の id で走り直した物も別の出来事（5 章の `fell`）なので、起動は始めの時刻で分ける。同じ run を 2 度送ると、Phoenix（21.0.0）は二重にも上書きにもせず、先に受けた span を残して後の物を捨てる（`phoenix/db/insertion/span.py` が `span_id` の重なりで `DO_NOTHING`。2026-11-04 に見本の run を 2 度送り、span 1,214・トレース 1 本・費用の和が 1 度目と同じだった）。なので記録が変わった run（走り中に送った run など）を送り直しても、前に送った span は前の値のまま残り、新しい span だけが足される。今の値で見直すには、Phoenix の側でそのトレースを消してから送る。
- 確かめた事（2026-11-04 の工場の line の run の記録。出来事と会話 28・下請け 7）: 組んだ span は 1,214（LLM 421・TOOL 528）で、親の無い span は run の 1 つだけ・id の重なりは 0。計画を審査するノードの周 1 の下請け 2 つは往復 61 と 35、往復の `llm.token_count.prompt` の最大は 189,292 と 198,786。
- Phoenix で見た事（2026-11-04。手元の Phoenix 21.0.0 に、8.1 の守り（手元の送り先にだけ送り、proxy を通さない）と README の起こし方のとおり 127.0.0.1 へ見本の line の run を送った。外へは送っていない）:
  - 1,214 の span が全部届き、親の無い span は run の 1 つ。run の span の出力の表で、計画の段が 25.07 USD で一番高く、計画を審査するノードの周 1 が 9.32 USD。そのノードの span の下に Agent の道具 2 つと下請け 2 つが在り、下請けの往復は 61 と 35、往復の `llm.token_count.prompt` の最大は 189,292 と 198,786。
  - 裏で走る下請けは、60 ミリ秒ほどで返る Agent の道具の span の子として、自分の長さ（10 分ほど）のまま木に出る。子が親より後に終わっても、Phoenix は詰めずに出す。
  - トレースの木は最初に 1,000 span だけを出し、残りは「Load More」で足す。span の OpenTelemetry の状態は付けないので、Phoenix の Status の欄は Unset と出る（工場の状態は `works_factory.status`）。
  - Phoenix のページは、開いた人のブラウザから `api.github.com`・`pypi.org`（版と星の数）と `fonts.googleapis.com`（字体）を引く。`PHOENIX_TELEMETRY_ENABLED=false` はサーバーの利用統計を止めるだけで、この引きは止めない。引く物に span は載らない（引きを止めても画面は出た）。

## 8.1 送り先の決めと送り（`src/sendto.py`・`src/otlp.py`・`runtrace.py`）

- 何の物か: 8 章の span の木を、利用者が名指した OTLP/HTTP の受け口（手元に置いた Phoenix など）へ protobuf で送る。網に出るのは見る道具の中で `src/otlp.py` の 1 つだけ。決まりは E25 の 2、決めは `run-trace-otlp` の 2。画面（Phoenix）はリポジトリに入れず、工場は起こさない。工場の run の流れにも入らず、run の後に人が打つ時だけ動く。常駐の仕組みは足さない。
- 送り先の名指し: 既定の送り先を持たない（E14。持ち主の環境の値を書かない）。名指しは 3 つで、先に在る物を使う。
  1. 引数 `--endpoint`: そのまま使う URL（例 `http://127.0.0.1:6006/v1/traces`）。
  2. 標準の env `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`: そのまま使う URL。
  3. 標準の env `OTEL_EXPORTER_OTLP_ENDPOINT`: 土台の URL。`/v1/traces` を足して使う（土台が `/` で終われば `v1/traces` を足し、`/` を重ねない）。
  - 2 と 3 の意味の違いと 2 が勝つ順は OpenTelemetry の仕様の「Endpoint URLs for OTLP/HTTP」（https://opentelemetry.io/docs/specs/otel/protocol/exporter/#endpoint-urls-for-otlphttp）による。信号ごとの env は字のまま使う。空の値は未設定と同じに読む（同じ仕様の「Parsing empty value」）。
  - 名指しが無ければ 1 行の訳で止まる。http か https で番地を持つ URL でなければ拒む。URL の全体（番地の部分だけでなく道も）に `\`・空白・制御文字が在る URL と、番地の部分が `[v6 の番地]` か英数字と `.` `-` の名に任意の `:数字` でない URL（userinfo の `@` など）は、`--remote` が在っても拒む（requests は番地を `\` でも切るので、`urlsplit` の host だけで決めると手元と読んだ字が遠くへ繋がる）。`urlsplit` が `ValueError` を投げる形の崩れた `[...]`（例 `http://[::1]x.example.com/`）も traceback でなく拒む訳と終了の値 2 にする。query（`?` の後。`?api_key=` など）と fragment（`#` の後）を持つ URL も `--remote` が在っても拒む。URL は成功の 1 行・送りの失敗・SDK の誤りの文に出る。fragment は HTTP の頼みには載らないが成功の 1 行には字のまま出るので、鍵の置き場にさせない。OTLP の鍵は headers の env で渡す形にそろえる。
  - どの拒みも訳に URL を出さない。手元でない送り先の拒みも、送り先の名でなく名指した口（`--endpoint` か env の名）を出す。
- 手元でない送り先の拒み: span は会話と道具の中身（対象のリポジトリの字）を既定で持つので、送り先が手元でなければ `--remote` を付けない限り拒む。手元かは字だけで見る（`localhost` と、`ipaddress` で loopback の番地。ほかの名は名前を引かずに手元でないと扱い、安全な側に倒す）。
- headers: 送り先を env で名指した時だけ env から取る（`OTEL_EXPORTER_OTLP_TRACES_HEADERS` が `OTEL_EXPORTER_OTLP_HEADERS` に勝つ。空の値は未設定）。`--endpoint` で名指した時は付けない（利用者の shell に別の受け口の鍵が在っても、引数で名指した別の宛先へ出さない）。名と値は percent-decode し、名は小文字にする（仕様の「Specifying headers via environment variables」と SDK の `parse_env_headers` と同じ。自分で読むので、解かないと SDK に任せた時と違う鍵を送る）。名と値の前後の空白とタブ（W3C Baggage の OWS）は解く前に外す。`name=value` の形でない項と、解いた後の名か値に制御文字（改行など）が在る項は、値を出さずに番号だけで拒む。端の制御文字（例 `a=key%0A`）も、解いた後に strip で削って通さずに拒む（SDK の `parse_env_headers` は解いた後に strip するので削って送るが、改行の混じった鍵は写し違いの印なので黙って直さない）。
- 送りの形: `OTEL_EXPORTER_OTLP_TRACES_PROTOCOL`（勝つ）か `OTEL_EXPORTER_OTLP_PROTOCOL` が `http/protobuf` 以外（`grpc`・`http/json`）なら拒む。入口は HTTP の protobuf だけで送るので、黙って別の形で送ると grpc の口へ HTTP を送って分かりにくく落ちる。ほかの `OTEL_` の設定（証明書・client の鍵・時間切れ・圧縮）は拒まず使わない。証明書が要る送り先は送りの失敗で声高に落ちる。
- proxy: 手元へは利用者の proxy の env（`HTTP_PROXY`・`HTTPS_PROXY`・`ALL_PROXY` と小文字の名）を通さない（会社の proxy の env が在ると 127.0.0.1 への送りが proxy に切られた。2026-11-04 の手元の確かめ）。`otlp.py` は requests の `trust_env` を切った session を exporter に渡す。手元でない送り先では利用者の proxy を使う。圧縮は付けない。
- SDK に `OTEL_` の名を読ませない訳: OpenTelemetry の OTLP/HTTP の exporter（1.45.2 の源で確かめた）は、引数で渡しても env を読む。headers は env の物にいつも足し、引数は同じ名の鍵だけを上書きする（`_resolve_headers`）。圧縮・証明書・client の鍵・session を作る口（`OTEL_PYTHON_EXPORTER_OTLP_HTTP_TRACES_CREDENTIAL_PROVIDER`）も、引数が空なら env から取る。`Resource.create` も `OTEL_RESOURCE_ATTRIBUTES` を読む（`otlp.py` は `Resource` を直に作る）。なので「明示して渡す」だけでは足りない。
- 入口の順（`runtrace.py`）: 引数を読んだらまず `sendto.decide`（入力は引数の送り先・env・`--remote`、答えは送り先の URL と headers と proxy を使うか、か拒む訳の 1 行）で決め、拒む時は run を読まずに訳と終了の値 2 で止まる。送ると決まったら自分の過程の `os.environ` から `OTEL_` で始まる名を全部外し（選びは `sendto.dropped`。入口は 1 回の命令の過程なので自分の env を変えてよい）、run を読んで組み、`otlp.py` を関数の中で import して送る。拒む道は SDK の無い環境でも走り切る。受け口が受けなければ終了の値 1。
- 時刻の無い span: 8 章の組みは、時刻が 1 つも読めない下請けと時刻の読めない往復を、始めも終わりも無い span で返す（往復は会話の読めなかった物に数え、下請けは数えない）。OTLP の span は時刻を要るので、入口は送る前に `runtrace.timed` で、一番近い時刻の在る祖先の始めと終わりで埋め、印 `works_factory.time_from_ancestor`（true。名は工場の物の名の置き場 `trace.py` の `TIME_FROM_ANCESTOR`）を付け、埋めた数を読めなかった物とは別に最後の 1 行に出す（`祖先の時刻で埋めた span N`。時刻の読めない往復は会話の読みが読めなかった物に数え済みなので、そこへ足すと二重になる）。送らずに落とすと、その下の往復と道具が親を失うので落とさない。run の span 自身に時刻が無い run（時刻の在る出来事が無い）は送らずに止まる。
- span の作り: `otlp.py` は SDK の `ReadableSpan` に、8 章の決まった id と記録の時刻（ナノ秒。float を通さない）のまま組んで exporter に渡す（tracer で作ると id が乱数になる）。頼み 1 回に 256 span まで。
- 外のパッケージ: `pyproject.toml` の extra `trace`（`opentelemetry-sdk`・`opentelemetry-exporter-otlp-proto-http`・`requests`。版は止める。`outside-packages-ok`）。`requests` は `otlp.py` が直に import するので、exporter の依存に頼って黙って入る形にせず宣言する。protobuf は自分で組まない。
- 試験の隔離: 試験の子の環境（`tests/bin/hermetic.child_env`。E21）と試験を回す口の `scrub` が外す名に `OTEL_` を入れた（利用者の shell の `OTEL_EXPORTER_OTLP_ENDPOINT` で「送り先が無い」の試験が赤になり、`COMPRESSION`・`HEADERS` が読み戻しを割るため）。proxy の名は足さない（`scrub` は試験の過程の env も変えるので、全部の試験の網の扱いが変わる）。手元では `sendto` の答えが proxy の env を使わないので、proxy の名が在っても結果は変わらない（変われば守りが外れた印で、赤になるのが正しい）。
- 縛り方（比べた 3 案）:
  1. 採る: 守り（送り先の無い起動を止める・手元でない送り先を `--remote` 無しで拒む・入口が SDK を読む前に決める・headers と proxy の決め）を SDK の要らない関数と入口の順に置き、CI の 4 つの分けと `tests/changed.py` の両方で見送り無しで縛る（7 章の 7・8）。
  2. 採る: SDK の要る所（答えが exporter に渡ること・`OTEL_` の名が SDK に届かないこと・手元へは proxy を通さないこと）は、CI の job `trace` が `test_otlp.py` の 1 本だけを `--extra trace` で回す（7 章の 9）。旗 `WORKS_FACTORY_TRACE_REQUIRED`（名は `tests/bin/hermetic.py` の `TRACE_REQUIRED_ENV`。`scrub` が残し、`tests/shard.py` が試験の子へ渡す）で見送りを赤にする（`tests/shard.py` は全部が見送りでも成功を返すので、旗が無いと SDK が入らなかった job が緑になる）。集めの job `tests` は分けと `trace` の両方を待つ。採る訳: SDK が env を読む口の数に頼るので、人が見るだけだと SDK の版を上げて口が増えた時に気づけない。
  3. 採らない: 4 つの分けの全部に `--extra trace` を足す。全部の分けに SDK と protobuf を入れ、それでも `tests/changed.py` では見送られる。
  - 残る隙: run の中の確かめ `tests/changed.py` では `test_otlp.py` が見送られる。CI の job `trace` が照らす。
- E11 の 3 つの答え: 1 章の各項の終わり（Archon と ASF はトレースを送る物を持たない・下請けが LLM の呼び出しの 47%・`oss-as-is` で画面は Phoenix に任せる）。

## 8.2 採らない道: Claude Code から直に送る

- 何の道か: Claude Code の直のテレメトリ（`CLAUDE_CODE_ENABLE_TELEMETRY` と OTLP の env）で、役の会話の span を run の間に受け口へ送る。工場のコードを変えずに利用者が自分で開けられる: Archon は AI のノードの子の env を、自分の `process.env`（`CLAUDE_CODE_*` を消した物）に設定の層の env（`--config` の `env:`・対象の `.archon/config.yaml` の `env:`）を重ねて作り、重ねた後に消し直さない（止めた Archon `2886e883d` の `buildProviderSubprocessEnv`。`docs/design/archon.md` の「役の claude の env の届き方」と同じ道で、`CLAUDE_CODE_PROMPT_CACHE_TTL` が実物の run で効いている）。工場の柵は隔離した `settings.json` の `env` を拒むので、Claude Code の設定ファイルの道は開けない。

  1. run とノードと周の木が無い。ノードごとに別の claude の起動なので、run 1 本が会話の数だけの別々のトレースになる。Archon は span を持たず、設定の層の env は run ごと（ノードごとに替えられない）なので、`TRACEPARENT` でノードの下に入れられない。
  2. span に費用が無い（費用は指標と `api_request` の出来事だけ）。
  3. 中身は既定で伏せられ、`OTEL_LOG_USER_PROMPTS`・`OTEL_LOG_TOOL_DETAILS`・`OTEL_LOG_TOOL_CONTENT` で開く。
  4. トレースは beta（`CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1` が要る）。
  5. run の間ずっと受け口が起きている必要があり、無いと送りの失敗が役の stderr に出る。過去の run は見られない。

- 採ると決めた時だけの確かめ: 小さな graph（AI のノード 1 つ・下請け 1 つ）を、run の設定の層の env にテレメトリの名を書いて 1 回回し、手元の Phoenix に `claude_code.*` の span が届くかを見る。見込みの費用 0.1〜0.5 USD。今は回さない。

## 9 run を 1 枚で見るページ（`runpage.py`・`src/page.py`・`src/fill.py`・`src/ioflow.py`・`page/`）

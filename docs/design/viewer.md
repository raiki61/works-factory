# 見る道具（`viewer/`）の設計書

- 何の話か: 工場の作り（graph と block の図・指示の md）と、run（工場の 1 回の実行）の一覧と再生を、人が 1 枚で見る道具の設計。置き場の決めは持ち主の決め `viewer-in-repo`、決まりは `viewer/AGENTS.md` の E25、計画は `docs/plans/2026-10-28-viewer.md`（3〜7 章と 9 章の PR の切り方）。
- 今在る物（計画の PR T1〜T3）: 置き場・層の地図の行・読む部品（`src/shape.py`・`src/runread.py`・`src/session.py`）・1 枚の HTML の組み立て（`src/page.py`・雛形 `page.tpl.html`）・日本語の写し（`src/ja.py` と訳の控え `ja/paragraphs.json`。6.6）と、ページを書く入口 `flowview.py`。画面は下書き `docs/plans/2026-10-29-viewer-overview.md` の 6.6 の形へ R1〜R5 の 5 本で組み直している途中で、今の雛形は R1〜R4（下書きの 7 章の 5〜8）の範囲: R1（骨と静かな画面と図）・R2（run の再生。6.7）・R3（流れ。6.5）・R4（無駄の手がかり。6.5・6.9）。

## 1 E11 の 3 つの答え

## 2 層と頼り

- 層の地図 `docs/layers.json` の層 `viewer`（`may_use` は `shell`・`shared`・`lib`）。どの層の `may_use` にも入らない。
- 殻（`shell`）に頼るのは、run の家を殻と同じ順に引くため。読む殻の口は `bin/_lib/launcher.py` の `target_root`・`run_home`・その 2 つが止まる時に投げる `Stop`（見る道具は受けて文を出し、終了の値 2 で止まる）と、`bin/_lib/isolate.py` の `DIRS` と、`bin/_lib/place.py` の `cache_dir`（訳の控えを殻と同じ取り置きの置き場に置く）の 5 つ（`bin/AGENTS.md` に同じ 5 つを書く）。`target_root` を通すのは、殻が `--cwd` を実のパスと git の根に直してから `run_home` に渡すため（相対のパス・対象の下のフォルダ・symlink で違う家を引かない）。
- `lib` は `lib/runlog.py`（Archon の spend の測りの読み `measurement`・`tokens` と、記録の行の名の一部）を使う。`shared` は日本語の写しを組む口（`workflows/.shared/prompt.py` の `compose`）と、値の記録の在り処を node の道から引く口（`workflows/.shared/ports.py` の `include_folders`）に使う（6.6）。
- 照らし: 見る道具へ頼らない向きは `tests/layers/test_viewer_apart.py`（E25 の 1）、`lib/` が見る道具を import しない向きは `tests/layers/test_lib_blind.py`（地図から頭のフォルダを作る `scan.LAYER_IMPORT` に `viewer` が入る）。見る道具自身の `may_use` は機械で照らさない: import の照らしは頭のフォルダの単位で、`may_use` の 3 つの層の頭（`bin`・`workflows`・`lib`）がどれも許されるので照らす字が無い。block と graph の中の物を import しないことは人が見る（YAML と md と script の docstring を字として読むのは見る道具の役目で、頼りに数えない）。

## 3 起こし方とデータ

工場の clone の根から `uv run --isolated python3 viewer/flowview.py [--target <対象> [--run <run の id か頭の字>]] <出力の html>`。

- `--target` が無ければ今の木の作りだけを出す。在れば run の家の親の run の一覧を入れ、`--run` が無ければ一番新しい親の run を見る。
- 出力は工場の clone の下を拒む（ページに対象の字と会話の中身が入る）。拒みの文は見る道具が自分で持つ（`launcher.refuse_in_factory` は run の家のための文で、意味が合わない）。
- 出力は 1 枚の HTML（6.5）。網には出ない。
- データの欄: `made_at`（作った時刻）・`commit`・`target`・`runs`（一覧。行に結末の語 `outcome`。5 章）・`run`（選んだ run）・`runs` と `run` の費用 `cost`（metadata の `total_cost_usd`。空の run と走り中の run は、run 自身の行の費用の和で代える〔Archon の `nodeCostScope` と同じ数え方。子の run の費用は、親の run の子の run を起こすノード `workflow` の行（`accounting` が `node`）が載せる。子の run の行を別に足すと二重に数える〕。和を出すのは読む部品 `src/runread.py` の 1 か所で、雛形は数えない。どちらも無ければ空。5 章）・`shape`（図の作り。graph と item に札の 1 行 `what`。4.5）・`shape_from`（`run-copy` か `tree`）・`unmatched`（図に当たらないノードの道）・`texts`（会話の字を 1 つにした表。会話の欄は番号で指す）・`stages`（段の表・結末の頭の語の表 `outcomes`・段ごとの集計。6.8）・`run` の `ai_cost`（図の札ごとの AI の手番の費用。札の鍵 → 札とその中の AI の手番の費用の和で、中の出来事を束ねる器は足さない。`src/stages.py` が数え、雛形は札と板で読むだけ。6.8）・`waste`（無駄の手がかりの数え。6.9。run が無ければ空）。

## 4 作りの読み（`src/shape.py`）

- 根（pack のフォルダ）を引数で受け、今の木 `<clone>/workflows` と run の写し `<写し>/project/.archon/workflows/<pack>` を同じ形で読む。
- ノードの読み分けは種類の鍵（`loop_group`・`include`・`workflow`・`approval`・`wait`・`prompt`・`command`・`loop`・`cancel`・`bash`・`script`）のどれか 1 つ。0 個か 2 個以上は読み分けられない物として `problems` に出す。AI のノードの md（`prompts/<id>.md`）・script のノードの script（`scripts/<名>.py`）が無い物と、工場の名の頭で始まるのに木に無い `include:`・`workflow:` の先も `problems` に出す。工場の名の頭で始まらない `workflow:` の先（Archon 同梱の `archon-pr`）は工場の外の graph として印を付ける。
- 記録のノードの道（`a__b.c`。`__` は include で開いた子、`.` は `loop_group` の本体）を、`locate` が include と `workflow:` の先の graph へ辿って図の所に当てる。当てた所には、通った include・`workflow:` のノードを外から順に並べた道（`via`）を付ける（図が入れ子の graph へ外から入る道。6.7 の再生が使う）。

## 4.5 札の 1 行（`src/what.py`）

- 図のノードと block の札に「何をする物か」の 1 行を出す（持ち主の言葉 2026-10-29「正直全然なんのやつかわからないのも多い」。下書き `docs/plans/2026-10-29-viewer-overview.md` の 5.6）。見るたびに LLM で書かせず、工場に既に在る字から、種類ごとの順で最初に在る物の最初の文（括弧と `` ` `` の外の「。」まで）を選ぶ。読むのは設計書と、作りの読みが既に持つ字（YAML の説明・script の docstring・指示の md と日本語の写し）だけで、block の `src/` は読まない（E22）。
- 順: graph と block は、自分の設計書の「役」の見出し（設計シートの外の最初の物。見出しの下が箇条書き〔mode ごとの役〕なら、頭の印を落とした最初の項）→ YAML の説明が名指す設計書の中の、フォルダの名で始まる節の下の「役」（judge と eyes は `judge-eyes.md`）→ YAML の `description`。AI のノードは、設計書の「node の設計シート: <id>」の下の「役」→ 設計書の node の並びの行（`` `<id>`（…）: 説明 ``。見出しの括弧の外に「並び」を持つ節とその下の節の、囲みのコードの外の、id の直後に種類の括弧を持つ行だけ。port の節の同じ名の行と、別のノードの下の入れ子で出力の欄を並べた `` - `<id>`: … `` は拾わない。鎖の形 `` `a` → `b`: 説明 `` は 1 つのノードの行にしない）→ YAML の `description` → 指示の md の `You ` で始まる段落の日本語の写し（訳が無ければ英語）。script は docstring で、「受け皿」「返し」で始まる物は配線として札を細く畳む。呼ぶノード（種類 `block` は `include:`、`child` は `workflow:`）は呼ぶ先の graph の 1 行と、呼ぶ側での役（呼ぶ側の設計書の node の並びの行 → `with` の `mode` の値）。繰り返しは形から組む（「下の n ノードを最大 m 周回す器」）。承認・止め・bash は node の並びの行 → YAML の `description`。
- データ: graph と item の `what` に `line`（1 行）・`from`（出どころの文書と節）・`why`（出どころの段落の 2 文目より後ろ）・`role` と `role_from`（呼ぶ側での役）・`wire`（配線）。1 行が無い物は `line` が空で、札と板は「1 行が無い」と出す（黙って空にしない）。呼ぶ側での役が無く、呼ぶ先を 2 か所以上で使う include は「ここでの役は設計書に無い」と出す（札が同じ字で並ぶ所）。
- ページ: 札の主を 1 行（2 行で切る）にし、名と種類を下に小さく置く。板の頭に 1 行を大きく、出どころを小さく、なぜ在るかを畳みで出す。
- 1 行は今の木の設計書から引く（run の写しの図でも同じ）。docstring と指示の md は図を作った pack（写しか今の木）の物。
- 書き足し（1 行が無い 12 ノード・工場の中の語が残る 1 行・呼ぶ側での役が無い include）は別の仕事（下書きの 5.6.3）。

## 5 記録の読み（`src/runread.py`）

- run の家の `archon-home/archon.db`（名は `isolate.DIRS`）を読むだけで開く。run の一覧は run の表の親の行（`parent_run_id` が空）だけを読み、ログは読まない。行は id・グラフの名・状態・止まっている承認ノード（状態が `paused` の run だけ。DB の `node_suspended` の後に終わりの無いノード。繰り返しの中の待ちでは Archon が本体のノード `<器>.<本体>` と器の両方に `node_suspended` を書くので、待つ本体を持つ器は並べず、答えが入れば器も外す。止めた・放棄した run は `node_completed` を書かずに `cancelled` になるので、状態で絞る）・始め・かかった秒・費用（metadata の `total_cost_usd`。空なら DB のノードの終わりと後から書く費用の出来事〔`node_completed`・`node_failed`・`node_deferred_usage`〕のうち自前の費用の行の `cost_usd` の和で、run 自身の行だけを足す。自前かは Archon の `nodeCostScope`〔`node-record-serialization.ts`〕と同じ: `accounting` が `node` の行で、`accounting` の無い古い行は `aggregate` が true でなければ自前。`compose_fan_out` の instance の終わりの行〔出力の欄 `type` が `compose_fan_out_instance`〕は、Archon の resume の和〔`dag-resume-snapshot.ts`〕と同じくその中の全部の正として足し、中の行〔道の頭が `<instance の道>__`〕は外す。費用の欄を持つ行が 1 つも無い run は和を出さず空のまま〔bash だけの run を無料の AI の run に見せない。`dag-executor.ts` の `persistRunUsage`〕。`total_cost_usd` と和の両方が在れば大きい方を出す: Archon は `total_cost_usd` を run の末尾〔待ち・落ち・終わり。`dag-executor.ts` の `persistRunUsage`〕だけで書き、SIGTERM で落とす道〔`packages/cli/src/utils/owned-run-termination.ts` の `failWorkflowRun`〕は書かないので、承認で起き直して走っている run と、その後に SIGTERM で落ちた run の `total_cost_usd` は前の待ちの時の古い値で、費用は減らないので今の和より小さい。答え待ちと終わった run は `total_cost_usd` が正で、和と同じか大きい。子の run の費用は、親の run の子の run を起こすノード `workflow` の行（`accounting` が `node`）が子の総額として載せ、metadata の `total_cost_usd` もこの行を通して子の分を含む。子の run の行を別に足すと二重に数える。選んだ run の費用も同じ口）・落ちの訳の頭の 1 行（DB の `workflow_failed`。状態が `failed` の run だけ。落ちた後に起き直して終わった run は `workflow_failed` の行を残す）・結末の語 `outcome`（line の返すノード `result` の出力〔DB の `node_completed` の `node_output`〕の欄 `outcome`。`result` の出力が無い run〔ほかの graph・`result` まで走っていない run〕と、出力が読めないか欄が字でない run は空。語は `lib/report.py` の `OUTCOMES` の 10 語の 1 つ）。
- 出力の中の欄の名（人の答え待ちの出力 `{decision, text}` の `decision`・`result` のノードの名と出力の `outcome`）は Archon でなく工場の記録の名だが、読む名は Archon の名と同じく `src/runread.py` の 1 か所に置く（`ANSWER_DECISION`・`RESULT_NODE`・`RESULT_OUTCOME`。字の読みは `runread.field`）。`result` の `stop_reason` は読まない（止まった段は記録の事実から引き、`stop_reason` では引かない。6.8）。
- run の始めとかかった秒は、run の行の始めと終わりでなく、出来事の最初と最後の時刻から出す（一覧は DB の出来事の表の `created_at`、選んだ run は子の run を含むログの出来事の始めと終わり）。承認の答えで起き直した run は、Archon が run の行の始めを起き直した時刻に書き換える（`packages/core/src/db/workflow-run-resume.ts`）ので、行の値では答えの後の数分しか出ない。出来事の無い run だけ行の値を使う。選んだ run の始めは、ログの出来事の最初の始めと、一覧の始めと同じ DB の出来事の最初（run の始めの印 `workflow_started` を含む）の早い方にする（DB の時刻は秒までの切り捨てなので、同じ秒ならログ。ログだけだと始めの印からノードの始めまでの数秒が抜け、一覧と分の丸めで割れる）。終わった run（子の run も）の終わりは、DB の最後の終わりの出来事（`workflow_completed`・`workflow_failed`・`workflow_cancelled`）の時刻と、ログの出来事の最後の終わりの遅い方にする（SIGTERM で落ちた・待ちのまま止めた run はログに終わりを書かないので、ログの出来事だけでは一覧と食い違う。DB の時刻は秒までの切り捨てなので、DB だけだと最後のノードの終わりより前になりうる）。一覧（DB の出来事だけを読む）と選んだ run のページの長さは、秒の丸めの内で合う。終わりの無い出来事（待ちと、止めた・落ちた run で走り中のまま止まった AI と機械のノード）は、その run の終わりの出来事のうち、出来事の始めの後の最初の物（始めと同じ秒の物も。DB の時刻は秒までの切り捨て。ただし同じ秒の内で始めの前にログの起き直しの行〔`workflow_resume`・`workflow_start` の 2 つ目から。最初の行は run の始め〕が在れば、その秒の落ちは始めの前〔落ちた後に起き直してから始めた〕として数えない。落ちた後の走り直しの分け〔下の状態の訳〕も同じ。`runread.RESTART_ROWS`）の時刻で閉じ、印 `cut`（true）を付ける（記録で確かめた終わりと見分ける。人の答え待ちの和もそこまで数える。落ちた後に起き直した run は、前の起動の走り中のノードを最後の終わりでなくその落ちで閉じ、状態を落ちにする〔run の最後の終わりの止まり方で言うと、完了した run で人が止めたように読める〕。Archon は起き直す時、終わっていないノード〔走り中・待ち・落ち〕に前の起動の id を使い直す〔`dag-resume-snapshot.ts` の `unfinishedInvocations`〕ので、閉じる終わりは出来事の最後の始め〔`last_start`〕の後の物から選ぶ。落ちは過去の事実なので、落ちた後に起き直してまだ走っている・答えを待っている run でも、前の起動の走り中・待ちのノードはその落ち〔最後の始めの後の最初の `workflow_failed`〕で閉じ、走り中の物を落ちにする。起き直した後に走り直したノードは、前の落ちでは閉じない）。閉じる時刻は始めより前にしない（長さを負にしない）。雛形は終わりの無いまま残った出来事をこの印で見つける（閉じた出来事は終わりの欄が埋まる）。閉じる時刻は DB の書き方からログの書き方（`YYYY-MM-DDTHH:MM:SS.000Z`）に直して入れる（雛形は時刻を `Date.parse` で読み、再生の歩を字で並べるので、T も Z も無い DB の書き方は手元の時差で読まれる）。走り中の run は最後の出来事までの長さ。子の run の行も同じく、その子と孫の出来事から出す。DB の時刻は秒までで時差を持たないが UTC（`datetime('now')`）として読み、ログの時刻と比べる。読めない時刻の行（字でない時刻も）は、その時刻を数えずに進み、読めなかった物（`unread`）に数える（ページを落とさない。段の集計と無駄の手がかりには読める時刻か空だけが渡る）。
- 一覧の並びと、run を名指さない時に開く一番新しい run は、出来事の最初の時刻の新しい順（出来事の無い run は行の始め）。行の始めで並べると、起き直した run が後に始めた run より上に来る。
- 長さの丸め（ページ）: 頭の帯・一覧・大きな数は分を整数に（秒に丸めて 60 秒未満は秒）、畳みの中は「分:秒」。同じ値はどの画面でも同じ丸めで出す。始めの時刻は、DB の書き方とログの書き方をどの画面でも秒までの `YYYY-MM-DD HH:MM:SS`（UTC）にそろえて出す。
- 選んだ run の記録は、DB の行の `output_root` から `logs/<run>.jsonl` を読む。子の run は DB の `parent_run_id` と metadata の `parent_node_id` で辿り、子の出来事の道の頭に親のノードの道を足す。run の写しは `<output_root>/workflow-source/runs/<run>/project/.archon/workflows`。写しが無い run は今の木で読み、`shape_from` を `tree` にする。

- 出来事はノードの起動（`execution.invocation.id`）ごとに 1 つ（落ちた後に同じ起動の id で走り直した物は、始めごとに分ける。下の状態の訳）: 始めと終わり（時刻はどれもログの書き方）・run の終わりで閉じたかの印 `cut`（閉じた出来事だけに在る。上の終わりの訳）・状態（走り中・待ち・済み・落ち。繰り返しの器は答えの後に同じ起動の id で `node_start` を書き直すので、待ちから走り中に戻す。起き直す前の落ちで閉じた走り中の出来事は落ち。前の起動で落ちて同じ起動の id で走り直した物は、落ちた起動の出来事を残し、走り直しを新しい出来事にして一度落ちたことを印 `fell` に持つ〔Archon は起き直す時、落ちたノードの前の起動の id と情報を使い直す。`dag-resume-snapshot.ts` の `unfinishedInvocations`。`node_error` の行も費用・トークン・会話を持つ。窓口の決め: 長さ〔段の AI の秒・時間の内訳・時間の帯も〕には走っていた間だけを数えて落ちから起き直しまでを入れず、費用・トークン・往復・会話はどの起動の分も落とさず、会話は両方ともページから辿れ、最後が通った所の板に前の誤りを今の誤りとして出さない。落ちた起動の出来事は状態が落ちで、その時の誤りの字を持つ〕。SIGTERM で落とす道〔`owned-run-termination.ts` の `failWorkflowRun`〕はログに `node_error` を書かず DB に `workflow_failed` だけを書くので、前の始めと次の始めの間にその run の落ちが在る物も同じで、落ちた起動の出来事はその落ちで閉じて印 `cut` を付け、走り中だった物を落ちにする）・落ちた時の誤りの字（`node_error` の `error`）・費用（自前の費用の行だけ。自前かは上の費用と同じ `nodeCostScope` の形。束ねた行は数え直さない）・模型とトークンと往復の数・会話の始まり方（`binding.sessionOrigin`。続けた会話は `resumed`）・道具の呼び出し（`provider_event` の `tool_call` と `tool_call_update` を試み〔`attemptId`〕で結ぶ）・script と bash の出力の終わり（`exec_output`）・出力（DB の `node_completed` の `node_output`。通った起動の出来事だけに付け、同じ起動の id の前の落ちた出来事には付けない。ページには 20,000 字で切って載せ、切る前の字の sha1 を `digest` に持つ）と、出力が指す run の置き場の小さなファイル（`archon_artifact` の `run_id` と `path`。絶対パス・`..`・symlink で `artifacts/runs/<run>/` の外を指す物と、NUL の字を持つ物は読まずに `unread` に数える。E25 の 2 の読むだけの範囲。読みで OSError が出る物〔長すぎる path・読む権限の無いファイルなど〕も、ページの組み立てを落とさずに `unread` に数える。置き場に無いファイルは数えずに進む）・その run の置き場の根（`artifacts`。日本語の写しが値の記録を引く。6.6）。
- 行の型と道具の出来事の型は、止めた Archon の型の和の全部を読む型と読まない型（訳つき）に分けて持つ。知らない型の行・JSON の object でない行（`123`・`"x"`・列）・object の行の中の欄の形が違う行（型の欄 `type` が字でない・`execution`・`event` が object でない・`loopPath` の周が object でない・周の番号が整数でない・会話の id の頭や step・試みの id が字でないなど。1 行は、書き込む値を全部取り出して形を確かめてから出来事に一度に書くので、途中で止まった行は出来事を変えず、後で使う段の集計と会話の読みで落ちない。`runread.SHAPELESS`。ノードの行の欄は、どの出来事か・状態・時刻を決める要の欄と、添えるだけの欄〔終わりの行の会話の id の頭・会話の始まり方・模型、落ちの誤りの字〕に分け、要の欄の形が違えば行ごと数え、添えるだけの欄の形が違えばその欄だけを捨てて行の残りを読み、欄の形が違う行に 1 つ数える〔要らない欄 1 つで通ったノードを走り中に残さない。`runread._side`〕。DB の出力の行〔`node_completed`〕の形の違いは、開いた run と読んだ子の run の物だけを数える〔DB は全部の run の行を持つ〕。step_name の無い `node_suspended` は待ちから読み飛ばし、開いた run の物を数える）・ノードに当たらない道具の出来事は `unread` に数え、黙って落とさない（ページを作れずに落ちない）。記録の字の片割れのサロゲート（JSON の `\ud83d` だけ。UTF-8 に書けない）は U+FFFD に置き換える（`runread.mend`。出力の字と `digest`・会話の字・ページの全体）。走り中の run は `live` と作った時刻を出す。答えを待つ run（状態が `paused`）には答える殻の命令の 1 行（`answer`）を付ける。答えが入って次へ進む前の間（Archon は答えを run の metadata の `wait` に書くだけで、状態は `paused` のまま `node_completed` も書かない）のノードは待ちに数えない（Archon の `runAttention` と同じ。名は `schemas/workflow-run.ts` の `workflowWaitStepName`）。承認ノードの答えはノードの出力（`wait: attention` の `{decision, text}`）から読む（`gate_decision` の行は工場が使わない古い `approval:` だけが書く）。

## 6 会話の記録の読み（`src/session.py`）

- 隔離した Claude Code の設定（`claude-config/projects/`）の中から、記録の `binding.sessionPreview`（会話の id の頭）で会話の記録を探す。Claude Code が消した古い記録は結べない。頭が 2 つ以上の記録に当たれば、黙って選ばずに読めなかった物（run の `unread`）に数える。頭は 16 進の字と `-` だけを通し（Claude Code の会話の id は UUID）、ほかの字（`/`・`..`・glob の字）を持つ頭は置き場の外や別の会話に当たるので、探さずに読めなかった物に数える。
- 続けた会話（出来事の `sessionOrigin` が `resumed`）の記録は、前の会話の往復を元の時刻のまま写して持つ（続けるたびに新しい会話の id の記録を作り、前の記録には書き足さない。ノードの始めの行の `sessionPreview` は前の会話、終わりの行は新しい会話の頭で、出来事は終わりの行の頭を持つ。2026-10-30 の工場の run の記録で人が確かめた。Claude Code の版は止めていない）。その出来事の始めより前の往復に `copied` を付け、無駄の手がかり（6.9）の返事の数・道具の呼び出し・読み直し・空いた往復・大きな結果・積み上がりのどれにも数えない（写し元の会話と二重になる）。ただし最初の新しい往復の前の空きは、写した最後の往復から測る（続けた会話の最初の往復も、cache の保ち時間を越えて空けば数える）。流れ（`seq`）には残す（LLM に入った物なので）。読めない時刻の往復は時刻を持たず、読めなかった物に数える。
- system と道具の一覧は `api-request-shape`、添え書き（system の片と `<system-reminder>` の片）は `api-request-blob` から取る。この 2 つの型が普通の利用者の Claude Code でも出るかは確かめていない。型の行が在ったかを `recorded` に持ち、無ければページは欄を空にせず「記録に無い」と出す。
- Claude Code の版は工場が止めていないので、記録の形は試験で照らさない（人が見る）。行の型は、読む型と読まない型（訳つき。`session.py` の `UNREAD_TYPES`。添え物・API の頼みの印・待ち行列の印・会話の題など、LLM に入った字を別の型から読む物と中身を持たない物）に分ける。どちらでもない知らない型の行と JSON の object でない行と、型の欄 `type` が字でない行と読む型の行の中の欄の形が違う行（`message`・`shape` が object でない・`content` が字でも列でもない〔字は字の片 1 つとして読む。API の形で許される書き方。道具の結果の `content` も同じ〕・字の片に `text` が無いか字でない〔空の列・0 などの偽の値も〕・道具の呼び出しの id や道具の名が字でない・往復のトークンや費用〔`cost-state` の `totalCostUSD`〕が数でないなど。1 行は、書き込む値を全部取り出して形を確かめてから流れ・往復・添え書き・字の束に一度に書くので、途中で止まった行は何も変えない。`runread.SHAPELESS`。ページを作れずに落ちない）だけを数えて返し、ページの「読めなかった物」の数に入れる（読まない型まで数えると、帯の数が本当に読めなかった物を指さない）。ただし読まない型のうち字を別の型から読む物（`session.py` の `READ_FROM`。`attachment` は `api-request-blob` から、`api-request` は `api-request-shape` と `api-request-blob` から読む）は、代わりの型が記録に無い会話では知らない型と同じく数える（代わりが無ければ LLM に入った字が帯から消える）。
- 往復の印は、usage を持つ行を待たずに往復（新しい `message.id`）の最初の行で置き、usage は後の行で埋める（usage の無い返事が混じっても往復の数がずれず、どの返事にも usage が無くても返事と道具の呼び出しが消えない）。往復は最初の行の時刻（`at`）を持ち、道具の呼び出しは切る前の入力の字の番号（`text`）を、会話は作業の場所（`cwd`。最初に `cwd` を持つ行の値）を持つ。どれも無駄の手がかりの数え（6.9）が使う。

## 6.5 ページ（`src/page.py`・`page.tpl.html`）

- ページは 1 枚で完結する（E25 の 3）。データは雛形の `<script type="application/json">` に、JSON の字の `<` を全部 `\u003c` にして埋める（記録の字の `</script>` や `<!--` が script の中身を閉じない）。雛形の印は 1 度ずつ埋め、埋めた字の中の印の字は埋め直さない。外の道具は埋めず、網にも出ない。
- 画面の形は下書き `docs/plans/2026-10-29-viewer-overview.md` の 6.6（9 章の決め 6「ゼロベースで再構築」）。今の雛形は R1〜R4（7 章の 5〜8）の範囲: 頭の帯（run の 1 行・タブ・明るさの札・戻る札の場所）・流れ（段の地図と時間の帯）・無駄の手がかり・図と再生（図と板と再生の帯）・run の一覧・ログ・読めなかった物。画面の間の口と戻り先（R5）は後の PR で同じ雛形に積む。タブの並びは 流れ → 無駄の手がかり（run が在る時だけ）→ 図と再生 → run の一覧 → ログ →（読めなかった物）で、開くと流れ。
- 無駄の手がかり（下書きの 6.6.2 の 2）: 数えの欄 `waste`（6.9）を読むだけで、雛形の中では数えない。頭に主張 1 文（上の 3 つの AI の手番の費用の割合）、欄 1 の費用の大きい順（上の 3 件の行と、全部の表は畳み）、欄 2〜6 のカード（大きな数 1 つ・主張 1 文・畳みの内訳）、数えられない物の畳み。欄 1 の行の頭に「AI」、欄 3・4 の行の頭にそのノードの種類の札（図と同じ札の関数。下書きの 6.6.16 の 6）。行から図へ移る口は R5。
- 見せ方の型（下書きの 5.7・6.6.1）: 字の段は 4 つ（40/600・22/600・15/400・12/400）、枠の線でなく面と余白で組を分け、細部は `<details>` で畳む。色は全部 CSS の札（変数）で持ち、dark は札の値だけを替える（6.6.12）。既定は `prefers-color-scheme` に従い、頭の帯の札で 自動 → ライト → ダーク と回す（保存はしない）。字は地と 4.5:1 以上、状態を伝える縁と面は地と 3:1 以上（6.6.17 の 5）。トークンの 4 分けの帯は隣り合う 2 つが 3:1 以上で、真ん中の「cache に書いた」を明るさの逆の端に置く。丸めは雛形の 2 つの関数（`mins`・`mmss`。6.1）。動きを減らす設定に従う。
- 図（6.6.11・6.6.15〜6.6.17）: 線と座標で並べず、札を字の流れのように左から右へ並べて幅で折り返す。line は段（6.8）を行にし、行の中を依りの層ごとに「→」で区切る（ほかの依りを通って届く依りは層の計算に数えない）。段の表の列 `wiring` の配線は line の一番上だけ既定で畳む（「配線も出す」で出す）。この run で走らなかった段は 1 行に畳む（再生の今の札が在る段は畳まない。「配線も出す」の時の配線の歩）。図を作り直す操作（入れ子の開け閉め・道具の行のチェック・畳んだ段の「開く ＋」）を鍵盤で押しても、手前（フォーカス）は同じ物に戻り、消えた物は代わりの札（閉じた入れ子の札・開いた段の最初の札）に移る。札は 1 行で、種類の語の札（AI は墨の面・人は 2px の縁と太字・機械は語の札なし）・何をする物かの 1 行（作りの読みの `what`。無ければ「1 行が無い」）・この run での姿の語（回数・費用・飛んだ・■ ここで止めた・✕ 落ちた）。入れ子（block・子の run）の札は押すとその場で中を字下げで開き、札と出来事の鍵は入れ子の場所ごと（出来事の `via` の鎖から組む）。自分を呼ぶ子の札は、この run にその子の出来事が在る時だけ開ける。line から辿れない graph だけは選びで根を替えて単独で見る。

- 流れ（下書きの 6.6.2 の 1・6.6.8 の頭の 1 文・6.6.13 の 1・3・6。R3）: 頭に主張 1 文と補い。主張は、終わっていない run なら人の答え待ちか走り中の段（「<段>で人の答えを待っている。」）、終わった run なら止まった段と止まり方（`stages.stop`・`stop_by`。「<段>で、人が止めた。」「<段>で落ちた。」）、止まった段が無ければ結末の頭の語（6.8）、それも無ければ run の状態の語。補いは長さと費用・止まった段の後で走らなかった段を続いた範囲ごとに「<段>から<段>まで走っていない。」（止まった後に走る報告の段は入れない。無ければ出さない）・費用の一番大きい段の割合。run を選ばない時は「依頼を受けてから報告まで、<n> の段。」。
  - 段の地図: 段の箱を 5 つずつ並べ、箱に番号・名・この run での姿（時間と費用・止まった・落ちた・飛んだ）。止まった段は注意色の太い縁、落ちた段は赤の太い縁、落ちた後に起き直して通った段（段の集計の印 `fell`。6.8）は「通った（1 度落ちた）」、走らなかった段は面を外した点線の縁と語。終わった run で終わりの無い出来事が残った段（走り中・人の答え待ちのまま）は、頭の主張と同じ止まり方の語と色（止まった段の止まり方、無ければ run の状態で「落ちた」か「止めた」）にする。地図の箱・畳みの表・図の段の行は同じ関数 `stageLook` で語と色を決め、図の札（終わりの姿と再生の終わりの歩）も同じ決めの関数 `openLook` で語と縁を決める。出来事の語（図の板・ログの行・再生の帯の「終わり（…）」）も、読む部品が run の終わりで閉じた出来事（印 `cut`）は同じ `openLook` の語にする（関数 `evWord`）。ただし落ちた後に起き直した run で、その落ちで閉じた出来事（印 `cut` で状態が落ち）は「落ちた」と言い、落ちた手番に数え、終わりの無いまま残った出来事には数えない。止まった段が無い run は、図の頭の 1 文もその止まり方の語と印で言う。出来事が 0 件の run は段が空なので時間の帯を出さない。run を見ている時は、この run の道に無い段（段の集計の状態 `none`。設計の段はテーマの run だけ）を出さない。run を選ばない時は塗らずに段の 1 行の説明を出す。段の説明と次の段へ渡す物（段の表の `line`・`hands`）は畳み。
  - 時間の帯（run を見ている時だけ）: 段を行、run の始めからの時刻を横にとった HTML の %。左に段の名（字の幅で切らない）、右に段の時間と費用。出来事を AI の手番・機械・人の答え待ち（`role`）で塗り分け、配線のノード（`through`）と中の出来事を束ねる器（`role` が `group`）は描かない。カードの主張は人の答え待ちの長さと割合（無ければ一番長い段）。段ごとの時間・人の待ち・AI の手番・周・往復・費用の表は畳み（「分:秒」）。
  - 再生の位置の共有（6.7）: 帯を押すと、押した時刻より前か同じで一番後の歩へ `go` で移る（待ちの中を押すと待ちの始まりの歩）。帯は鍵盤でも押せ、その時は段の帯の最初の絵の歩（帯に描く出来事の始まり。配線の歩より前に戻らない）へ移る。押せる物にするかも帯に描く歩で決め、帯に描く歩の無い段（配線の歩だけが走った段も）の帯は押せる物にしない。再生中は帯に今の時刻の縦の線、地図に今の段（青い面）・通った段・まだの段（配線でない出来事だけで数える）、帯の下に「再生の今: 段 · 時刻 · 歩。図と再生で歩く →」を出す。「やめる」の後は終わりの姿に戻る。歩く操作は流れでは受けない（再生の帯は図と再生だけ）。
  - 読めなかった物が 0 件の時は、流れの一番下に 1 行で出す。
- 依存の線は、試作として図の頭の選びで「引かない（前と次の札を淡い青に）」と「選んだ札の前後に引く」を並べて見られる（6.6.17 の 1。どちらを採るかは持ち主が本物の run の図で選ぶ）。
- 費用は雛形の中で数えない: 札と板は札ごとの AI の手番の費用 `run.ai_cost` を読み（板の語は「AI の手番の費用」）、ログの段の見出しは段の集計の費用（流れの地図と同じ値。段の表の外の run は run の費用）を読む。
- 押せる物は `button`（見た目は字の口や札のまま）にし、`href` の無い `a` と押せる `span` を置かない。button にできない行（run の一覧とログの行）は、Enter と空白で押したのと同じに動かし、支援技術には `role="button"` と開いているか（`aria-expanded`）で伝える。
- run の一覧は 1 行 1 本（run・結末・始め・長さ・費用）で、行を押すとその run のページを作る命令を出す。結末は今の run だけ頭の帯と同じ語（止まった段が在ればその語）で、ほかの run は結末の頭の語、語が空なら状態の語（6.8 の決め順）。ログは段の見出しの行と出来事の行（1 行 1 件）を詰めて並べ、行を押すと出来事の面を開く。読めなかった物のタブは 1 件以上の時だけ出し、0 件の時は流れの一番下に 1 行で出す。

## 6.6 日本語の写し（`src/ja.py`・`ja/paragraphs.json`）

- 日本語の写しは、AI のノードへの英語の指示を段落ごとに日本語に訳した、人が読むための射影で、LLM には渡さない（持ち主の決め `prompt-values-for-viewer`・`viewer-in-repo` の 4）。見るたびに LLM で訳さず、訳の控え（段落の字の sha1 の頭 16 字を鍵、訳を値にした JSON）から引く。
- 控えは 2 か所（計画の 5.2 の案 J1）: 工場の指示の md（pack の `<block>/prompts/` と `.shared/prompts/`）の段落の訳は `viewer/ja/paragraphs.json` に入れる。それ以外（Claude Code の字・run の時に入った字。対象の字を含みうる）は利用者のキャッシュ（`place.cache_dir` の下の `viewer/ja-cache.json`）に置く。引く時は 2 つを合わせ、リポジトリの方が勝つ。
- 段落は、空の行と組み立ての印の行（段落の選びの印・道具の印・断片だけの行）で区切った行の塊。英字が 40 字を超え、かなが英字の 3 分の 1 未満の塊だけを訳す。訳は、差し込み口（`{name}`・`{shared:…}`・`{part:…}`）と字の `{{`・`}}` と印の頭の字を英語と同じだけ持ち、印の行を持たない物だけを使う。合わない訳は取り込まず、組む時も英語のまま残すので、写しの md の木は英語の木と同じ値と段落の選びで組める。
- 写しの組み方（計画の 5.3）: 図を作った pack（run の写しか今の木）の md を、段落を訳に差し替えて一時のフォルダに同じ形で書き、run の値の記録（`<md>-viewer-values-<n>.json`）の `values` と `when` で、工場の組み立ての口 `prompt.compose`（block と共通の断片の根を受ける。`render` と `emit` も通る口）に組ませる。値の記録の在り処は、出来事の run の置き場と、node の道から `ports.include_folders` が引く include の道。
- どの記録がどの出来事の指示か: place に書かれた英語の指示（`<md>-prompt-<n>.md`）の字が、その出来事の会話に入った指示の字と同じ物（md の名がノードの id と違う prep と、会話を続ける輪にも当たる）。当たった中にノードの id と同じ名の md の物が在ればそれだけ（続けた会話には前のノードの指示も入っている）。会話の記録が無ければ、ノードの id と同じ名の md の物。同じ所の出来事の数と記録の数が同じなら書いた順に 1 つずつ当て、違えば全部の回を並べる。当たる記録の無い出来事（値の記録を書かない組み方の指示）には写しを出さない。
- ページ: 図の板の md と system の md・出来事の組み直した指示・会話の system と添え書きと指示に、日本語の写しを畳みで添える。訳の無い段落の数（指示の md・会話）を帯の注に出す。
- 訳の控えの足し方: `flowview.py --ja-batches <置き場>` がページに出す字のうち訳の無い段落を約 3.5 万字ずつの束（`batch-<n>.en.txt`。clone の外）に書く。訳すのは取り次ぐ会話で、同じ鍵の行の訳を `batch-<n>.ja.txt` に書く。`--ja-import <置き場>` が、今の木の md の段落の鍵の訳だけを `viewer/ja/` に、ほかをキャッシュに書く（合わない訳は拒んで名指す）。md を直して古くなった鍵は残っても英語で出るだけで、`--ja-prune` が消す。
- 始めの控え: 窓口の手元の控え（904 段落）のうち、今の木の md の段落に当たる 578 段落を、取り込みの口で入れた。残りは会話の字の訳で、リポジトリに入れない。

## 6.7 再生（`page.tpl.html` の中のスクリプトだけ）

形は下書き `docs/plans/2026-10-29-viewer-overview.md` の 6.5.1・6.6.8・6.6.11・6.6.13 の 1・6.6.15 の 3・6.6.16 の 2 と 4・6.6.17 の 9（R2。流れとの共有は R3）。

- 終わった run を後から 1 枚で歩く。ページの中のスクリプトだけで動き、別のファイルを読まない（E25 の 3）。
- 1 歩は、run の出来事（ノードの起動ごと）の始まりか終わりの 1 つで、時刻順に並べる（同じ時刻は始まりが先）。終わりの無い出来事（走り中・待ち）は始まりだけ。繰り返しの周は周ごとに別の出来事なので、そのまま 1 周ずつ歩く。子の run の出来事は親の出来事と同じ並びに時刻で入る。
- 飛んだノードは歩にしない（数が出来事より多く、歩の大半が飛びになる）。時の位置が飛んだ時刻を過ぎ、その所がまだ走っていなければ「飛んだ」に見せる。
- 再生の位置（今の歩の番号）はページに 1 つだけ置き、変えるのは `go`（歩く）と「やめる」（run の終わりの姿へ戻る）の 2 つだけ。図が見えていない時、`go` は図を描き直さず「遅れている」の印だけを立て、図と再生のタブを開いた時に今の歩へ合わせる。`go` と「やめる」は、どちらも流れの今（地図の今の段・帯の縦の線・帯の下の 1 行）を映し直す（6.5 の流れ）。
- 再生の帯は 1 つで、図と再生のタブにだけ画面の下に固定して出す（‹ 1 歩戻る・▶ 再生と止める・› 1 歩進む・■ やめる・位置のつまみと、今の歩の 1 文「段 · 何をする物か · 歩の番号 · 時刻 · 始まりか終わり · 周 · 子の run · 記録の道」）。ページの下の余白と板の下の端は帯の測った高さだけ空ける（決め打ちにしない）。帯はいつも一番上の層で、狭い時に図に重ねる板も帯を隠さない。鍵盤の ← → と空白は帯が見えている時だけ受け、字の欄・つまみと押し物の上の空白は除く。つまみの右の端（歩の数と同じ値）は終わりの姿で、開いた時と「やめる」の後はそこに在り、‹ とつまみの ← はどちらも最後の歩へ行く。右の端より先は無いので、終わりの姿では › と → もつまみの → と同じく動かない（▶ は最初の歩から歩き始める）。つまみを右の端へ戻すと「やめる」と同じ。
- 図は今見ている graph（根）に留まる。今の歩の `via` の鎖の入れ子を自動で開き、中の今の札を青い面にして、頭の帯と再生の帯の間に入るまで送る。次の歩で鎖から外れた入れ子のうち、自動で開いた物だけ閉じ、人が開いた物は閉じない。人が自動で開いた物を閉じたら、再生がその鎖を抜けるまで開き直さない。「やめる」で自動で開いた物は全部閉じる。再生中に根を替えた時（line の外の graph から戻した時も）は、図を作り直した後に再生の今へ合わせ直す。
- 札の姿は終わりの姿と同じ型に「今」を足す: 今の札は青い面と白い字と淡い青の輪（種類の札は白い縁と字、AI は白い面に青い字）、繰り返しの器の出来事の歩は器の点線の枠を青い縁と淡い青の輪にし、今を中に持つ開いた入れ子の札は淡い青の面と青い縁と「今は中」、ここまでに走った札は縁と面、まだの札は灰。段の行は今の段を淡い青の面にし、左の列に「再生の今」「通った」「まだ」（通ったは配線でない出来事だけで数える。6.8）。再生中は札に費用と回数を出さず、止めた・落ちた所の太い縁は終わりの姿だけに出す（再生の最後の歩を除く。最後の歩では、終わりの無い出来事の札に `openLook` の語と縁を出す）。札の終わった状態は、終わりの姿も再生の歩も、札に当たる所（run・道・周）ごとの最後の出来事の状態で決める（段の集計と同じ訳。6.8）。なので最後の歩と終わりの姿の札が違うのは、終わりの無い出来事だけ。落ちた後に走り直して通った所の札は通ったで、終わりの姿で段と同じく「1 度落ちた」を添える。人が止めた札（`stages.stop_event` の所）は「ここで止めた」だけを出し、同じ札の前の落ちの縁を付けない。入れ子の「AI n」は終わりの姿の数のまま（再生の位置までの数へ替えると 1 歩ごとに数が変わって入れ子どうしを見比べられないので、替えない）。
- 既定で畳んでいる配線のノード（line の一番上で「配線も出す」が外れている時）の歩は、図に札が無いので、前の歩のうち図に見える一番深い札に今を残し、図の上の 1 文と帯の 1 文で「配線の歩（図では畳んでいる）」と言う。
- 歩くたびに板を開かない。板が開いている時だけ、板を今の札の物に替える。入れ子が閉じて図を作り直すと、選んでいた札が消えて板が閉じるので、開いていたかは作り直す前に控える。
- ▶ で歩いている時に帯が隠れたら（ほかのタブへ移った時）、▶ を止める。位置は保つ。
- 送りは、動きを減らす設定（`prefers-reduced-motion: reduce`）の時は飛ばす。

## 6.8 段（`viewer/stages.json`・`src/stages.py`）

- 段は、line（メイングラフ）の一番上のノードを人の言葉で畳んだ単位（受付・判定・計画・修正・報告など 11 個）で、見る道具だけの考え。流れの画面（段の地図と時間の帯）が使う。設計の下書きは `docs/plans/2026-10-29-viewer-overview.md`（#907）の 3〜6 章。
- E11 の 3 つの答え: Archon は持たない（Web の画面の run の詳細は、include を開いた平たいノードの図とログの並びで、ノードを段に畳む物と段ごとの時間は無い）。ASF も持たない。要る: 図とログからは、どこからどこまでが判定で、どこからが修正か・どの段に何分と幾らかかったかが読めない（下書きの 1 章）。
- 表の置き場は見る道具の中（持ち主の決め。下書きの 5 章の S2）。工場の文書の形に見る道具の都合を持ち込まない。行ごとに名・1 行の説明・受け渡す物（次の段へ渡る物の人の言葉）・説明の出どころ（`docs/design/line.md` の 1.3 の番号）・中のノードの id を持つ。ノードごとの「何をする物か」の 1 行は表に持たず、工場の字から引く（下書きの 5.6）。
- 結末の頭の語の表（`viewer/stages.json` の `outcomes`。データの `stages.outcomes`）: 結末の語 → 頭の帯の run の 1 行と流れの頭の 1 文に出す頭の語（「直した」「人が止めた」など。下書きの計画の 6.6.10）。人の言葉の表なので段の名と同じ置き場に置き、report の block の `src/` は読まない（E22）。語の組は工場の結末の語の正本 `lib/report.py` の `OUTCOMES` と同じ（工場が語を足すと照らしが赤）。雛形は、頭の帯の run の 1 行・流れの頭の 1 文（止まった段が無い run）・run の一覧の結末の列で、run の一覧の行の `outcome` をこの表で頭の語にする。止まった段が在る run の頭は止まった段と止まり方のまま。語が空の run は run の状態の語（終わった・落ちた・止めた）で代える。決め順は 止まった段 → 結末の語 → run の状態 で、止まった段は run の記録（ログ）を読んだ見ている run にしか無く、run の一覧はログを読まない（5 章）ので、同じ run の語が自分のページ（止まった段の語。どこで止まったかまで言える）とほかの run のページの一覧（結末の語）で違いうる。
- 出来事の段は、出来事の道の頭（line の一番上のノード）で引く。include・繰り返しの周・子の run の出来事も道の頭は line のノード。run が line の run でなければ段に集めない（表は line だけ）。
- 段ごとの集計（データの `stages.run`）: 状態（通った・落ちた・待ち・走り中・飛んだ・記録に無い。所〔run・道・周〕ごとの最後の出来事の結果で決める。落ちた後に起き直して完了した run で、前の起動で落ちた所が起き直した後に通った段は通ったにし、一度落ちたことを印 `fell` に残す。同じ起動の id で走り直した所も、読む部品が起動ごとの出来事に分けるので同じ〔走り直しの出来事も印 `fell` を持つ〕。窓口の決め。雛形の段の地図・畳みの表・図の段の行は「通った（1 度落ちた）」と出す。図の札も同じく所ごとの最後の出来事で決め、通った札に「1 度落ちた」を添える。6.7）・始めと終わり（段の出来事の最初と最後）・人の答え待ちの秒（`wait:` のノードの長さの和）・AI の秒と手番の数（AI のノードの長さの和と数）・往復の数（`turns`。Archon が数える出来事の往復の和）・周の数（`rounds`。繰り返しの本体の場所と周の番号の列 `loop` の組の違う物の数で、入れ子なら内の周まで。本体の場所は道を繰り返しの区切り `.` だけで切った物で、本体に直に在るノードと本体の include の中のノード〔`plan-rounds.design-turn` と `plan-rounds.plan__draft`〕を同じ周に数える〔受付 c31850 の足し 2e1ffb〕。同じ段を何周回ったかで、無駄な回り直しを見る）・費用（ドルの和だけ。4 分けごとのドルは出さない）・4 分けのトークン（記録の `input`・`output`・`cacheRead`・`cacheWrite` の和）。
  - 新しく読んだ分（`uncached`）と cache の内訳が知れない手番の数（`cacheUnknown`）は、工場の共通の口 `lib/runlog.py` の `add_tokens` と同じ訳で出す: `uncached` は `input` から cache の 2 つを引いた物で、cache の欄が欠けた手番（Archon では「知れない」の意味で 0 ではない。`docs/design/archon.md`）と `cachePartial` の手番が 1 つでも在れば出さない。`input` が cache の 2 つの和より小さい手番は引けないので数を `odd` に持ち、1 つでも在れば `uncached` を出さない（包みの関係は Claude Code と Archon の版で変わりうるので決まりとして照らさない）。
  - 中の出来事を束ねる器（繰り返しの器 `loop_group`・並べて起こす器 `compose_fan_out`・子の run を起こすノード `workflow`。`runread.GROUP_KINDS`）の出来事は、中の出来事と二重になるので数・長さ・費用に数えない。子の run を起こすノードの行には Archon が子の run の総額を載せ（`docs/design/archon.md`）、子の中の各ノードの費用も同じ段に入るため。

## 6.9 無駄の手がかり（`src/waste.py`）

- 選んだ run の記録と作りの読みから、無駄かを見る人が決める材料の数を機械で数える（データの欄 `waste`）。「無駄だ」とは断じず、数えた事実だけを置く。設計の下書きは `docs/plans/2026-10-29-viewer-overview.md`（#907）の 3 章の案 D と 5.5。画面（無駄の手がかりのタブ）は 6.5 の雛形が欄を読むだけで出す（下書きの 7 章の 8 の R4）。

  1. `top`: AI の手番（`agent`・`loop`）の費用の大きい順。費用の割合（手番の費用の和に対する物）・時間・往復の数（Archon の `turns` と会話の返事の数 `replies` の 2 通り。`replies` は写して持つ往復を外す）・4 分けのトークン。費用は手番の合計のドルだけで、4 分けをドルに割らない（値段の表を持たない）。新しく読んだ分 `uncached` は段の集計と同じ口（`stages.four`。`lib/runlog.py` の `add_tokens` と同じ訳）で出し、`input` が cache の 2 つの和より小さい手番は `odd` に並べる。

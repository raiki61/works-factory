## 1 block の全体

### 1.1 役

独立設計が在り、問いが立ち、目的の文が空でなければ、比べの役に、目的・独立設計・設計の後の前提・テストの実測と累積差分の起点・累積差分のファイルだけを渡し、構造の本質的な食い違いの有無で `pass` か `redesign-needed` を決めさせる。独立設計が問いは立たないと言っていれば比べず、検算の役に独立設計の返答の全体・目的・記録の制約・実測を渡して、仮定が偽と示せるか（`resolved`）、示せないか（`escalate`）を返させる。独立設計が無い・目的の文が空・問いが立つかの欄が無い時は、役を起こさず、どの訳かを分けて `unverifiable` にする。比べの役が「渡されていない」と書いた文と、実は渡していた前提の対を、人が突き合わせられる行にして返す。

### 1.2 port

入力（YAML の `inputs:`）。どれも判定・修正案・単位の目録・修正の結末を運ばない:

- `base`・`lang`・`answers`・`request`・`changed`（r1.md の 0.2）。`lang` の人に見せる欄は 2.4・3.4。
- `head`: `text: 修正前の HEAD（審査する変更の先の版）。空は HEAD`。既定 `""`。
- `base_label`: `text: 累積差分の起点の出どころの文（今の startrec.diff_base_label。例「PR #12 の根」）。空は書かない`。既定 `""`。
- `purpose`: `text: 元の目的の 1 文（目的の固定の purpose_text）。空は渡されていない（比べない）`。既定 `""`。
- `design`: `json(r2-design.schema.json): 独立設計の役の返答（独立設計の block の出力 design の先。{question_stands, reason, premise_invalid_reason?, design?, elements?}）。null は独立設計が無い`。既定 `null`。
- `design_reason`: `text: 独立設計が無い訳（独立設計の block の出力 reason）。空は訳が無い`。既定 `""`。
- `design_premises`: `json(r2-design-premises.schema.json): 独立設計の控え {node, given, withheld, seen, claims}（独立設計の block の出力 premises の先）。null は控えが無い（独立設計の後に来た答えを分けない）`。既定 `null`。

- `test_outcomes`: `json(r2-outcomes.schema.json): 全件の機械集計と完全な結果ファイルの参照 {summary, details, unmeasured}（試験の関門 final の出力 test_outcomes）。null は渡されていない`。既定 `null`。
- `tdd`: `json(r2-tdd.schema.json): 修正の段ごとの TDD の記録（段ごとに、組ごとの記録の配列か、読めない訳の字）。null は渡されていない`。既定 `null`。

形のファイル（`workflows/r2/schemas/`。名に block の名を付ける。r1.md の 0.7）:

- `r2-design.schema.json`: `{"type": ["object", "null"], "properties": {"question_stands": {"type": "boolean"}, "reason": {"type": "string"}, "premise_invalid_reason": {"type": "string"}, "design": {"type": "string"}, "elements": {"type": "array"}}}`。

出力（`returns: finish`、`outcome_field: ok`）: r1.md の 0.3 の欄（`questions` はいつも `[]`）に、2 つを足す:

- `premise_check`: 前提の検算の道の時だけ `{verdict, reason, key, resolution, facts}`、ほかは null。`verdict` は `resolved` か `escalate`。`key`・`resolution`・`facts`（次の run の制約に足す実測の字の配列）は `resolved` の時だけ中身を持ち、ほかは `""`・`""`・`[]`（今の `eyeverdict.premise_facts` と同じ決め）。役の返答が無い・語が約束の外なら `{verdict: escalate, reason: <落ちた訳>, key: "", resolution: "", facts: []}`（E35）。
- `notes`: 字の配列。最後の承認ノードと報告の R2 の行の下に並べる行（今の `eyeverdict.r2_input_lines` の行。比べの役が「渡されていない」と書いた文・そのうち渡していた物・独立設計の後に来た人の答え・2 つの役に渡した前提の入力と渡さなかった物。E45）。

`status` の決め（r1.md の 0.3）: 比べの役か検算の役の返答を読んで判定を組めば `ran`、独立設計が無い・目的の文が空・問いが立つかの欄が無いで役を起こさなければ `skipped`、port が読めない・起こした役の返答が無いか約束の外なら `failed`。

今との違い: 今は `design`・`design_premises`・`purpose` を pointer で、`changed`・`test_outcomes`・`records`（修正の段の出力の控えの欄。`tdd_unit` の pointer の先を `fixbeside.tdd` で読んだ）・`premises`（`constraints` を持つファイル）・`answers`・`start_answers` を eyes の入力で、差分の根・修正前の HEAD・起点の出どころ・依頼のファイルを始めの記録から読んでいた。出口は判定の行 `r2` と `premise_check {verdict, reason}` に、控えの pointer `notes`（`premise-inputs.json`）と `premise_reply`（検算の役の返り）を足していた。新しい形は、TDD の記録を読んだ後の値で受け（`fixbeside` は README の 9.1 で消える名の住処）、控えと検算の答えを値で返す。

### 1.3 node の並び（`workflows/r2/works-factory-r2.yaml`）

1. `intake`（script `intake.py`）: r1.md の 0.4 の 1。独立設計を読み（`src/due.py` の `read_design`）、`compare`（`compare_due`）と `premise`（`premise_invalid`）を決めて `intake.json` に書く。返り `{compare, premise, reason}`（`output_format`: 3 欄とも必須、`compare`・`premise` は boolean、`reason` は字）。port が読めなければ両方偽と訳。
2. `r2-compare-prep`（script `compare_prep.py`。`depends_on: [intake]`・`when: "$intake.output.compare == true"`）: 指示と system prompt を組み、貼った前提の控え `r2-premises.json` を書く。返り `{prompt, system}`。
3. `r2-compare`（AI。`prompt: "$r2-compare-prep.output.prompt"`・`systemPrompt: "$r2-compare-prep.output.system"`・`depends_on: [r2-compare-prep]`・r1.md の 0.8 の起こし方〔`@wf-eyes-core`・`[Read]`・`context: fresh`〕・`output_format` は今の `r2-compare` の物を字のまま）
4. `r2-compare-save`（script `save.py`。`depends_on: [r2-compare]`・`with: {name: r2-compare, reply: $r2-compare.output}`）
5. `premise-check-prep`（script `premise_prep.py`。`depends_on: [intake]`・`when: "$intake.output.premise == true"`）: 返り `{prompt}`。
6. `premise-check`（AI。`prompt: "$premise-check-prep.output.prompt"`・`depends_on: [premise-check-prep]`・`@wf-eyes-core`・`[Read, Grep, Glob, WebSearch, WebFetch]`・`context: fresh`・`output_format` は今の `premise-check` の物を字のまま）
7. `premise-check-save`（script `save.py`。`depends_on: [premise-check]`・`with: {name: premise-check, reply: $premise-check.output}`）
8. `finish`（script `finish.py`。`depends_on: [intake, r2-compare-save, premise-check-save]`・`trigger_rule: all_done`）: r1.md の 0.4 の 3 と 5 節。

`compare` と `premise` は同時に真にならない（`question_stands` が真か偽か）。2 つの役は互いを待たない（E9 の 2 つの筋）。

## 9 自分で決めた事

1. port を 14 個にした（README の 8.4 は `base`・`design`・`purpose`）。根拠: 今の 2 つの役は、独立設計の控え（後に来た答えを分ける）・人の答え・依頼の名指しの節・前提のずれ・記録の制約・テストの実測・TDD の記録・起点を受けている（E38〜E44）。`design` だけにすると元の能力が落ちる。独立の守りは「判定・修正案を運ぶ port が無い」の yes/no で同じ強さに保つ（README の 8 節の頭「詳しい port は各設計書で決める」）。
2. 最後の承認ノードと報告が読む控え（今の `notes`・`premise_reply` の pointer の先）を、出力の値 `notes`（行）と `premise_check`（`key`・`resolution`・`facts` を足した値）で返す。根拠: 読み手が block の place のファイルの名と読み口（`eyeverdict.r2_input_lines`・`premise_facts`）を知らずに済む（README の 4.4）。行の字と決めは今のまま。
3. 設計の後の前提の材料の前半（`src/premises.py` の `material`）を、independent-design の block の `src/premises.py` と同じ中身で写す。根拠: 作り直しの間は各 PR が自分の block だけを触る（README の 11.1）。2 つの block が使うので、組み込みで lib の 1 モジュールに寄せる（independent-design の 11 節の 4 の `marks.py` と同じ扱い）。
4. TDD の記録を、読んだ後の値で受ける（port `tdd`）。根拠: 今は修正の段の出力の pointer を `fixbeside.tdd` で読んだが、`fixbeside` は名の住処で消える（README の 9.1）。受け手は形だけを宣言し、どの block がどの欄で渡すかは graph の側（README の 4.1）。
5. `PREMISE_NO_REPLY` の字から、消える出力の欄の名 `premise_reply` を外した（1.5）。
6. 入口の控え `intake.json` は `read`（port が全部読めたか）を持ち、出口と支度は `read` が偽なら入口が落ちたと扱う。依頼のファイルは入口で本文を読み、無い・読めない（pointer やパスが壊れている時も）は port の誤りにせず `request_read: false` として、支度が段落 `request_unread` と `withheld` の行を入れる。根拠: 仕様の「読めなければ `request_unread` を控える（止めない）」。
7. port `constraints` は行の配列か、それを `constraints` の欄に持つ object（共通の形がそう通す）を受け、空は「（無い）」と書く。今は読めなかった時の「（記録の制約が渡っていない）」と空の「（無い）」を分けていたが、port の既定が空の配列で「渡されていない」と「無い」が同じ値になるため 1 つにした。`tdd` が null の時は今の空の並びと同じ「無い（修正の段が走っていない）」の行を貼る。

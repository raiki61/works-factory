### 0.2 共通の port

4 つの block は、次の port を同じ名・同じ形・同じ意味で持つ（使う block だけが持つ。どの block が持つかは各設計書の 1.2）:

- `base`（4 つとも）: `text: 累積差分の根の commit（入口の差分の根。差分の run では PR の根）。累積差分はここから作業ツリーの今の姿まで（未追跡の新しいファイルも入る）。空は HEAD`。既定 `""`。
- `lang`（4 つとも）: `text: 人に見せる欄（設計書の 2.4 などが node ごとに名指す欄）の言語。空は依頼の言語`。既定 `""`。
- `green`（r1・r3・r4）: `flag: 修正の後の最後の試験の緑が認証されたか。偽なら目の指示に「最後のテストの認証が通っていない」の 1 文を足す`。既定 `true`（単独の run は試験の関門を通らないので、文を足さない）。
- `policy`（r1・r3・r4）: `file: 人の方針の文書を run の頭で固めた写し。空は方針の文書が無い`。既定 `""`。
- `after`（r1・r3・r4）: `file: 直した後の構造の実測の控え（名は structure-after.json）。空は測っていない`。既定 `""`。
- `review`（r1・r3・r4）: `json(shared:plan-verdict.schema.json): 修正が使った修正案を審査した事前審査の最後の往復の結論 {round, verdict, blocks, why}。空のオブジェクトは渡されていない`。既定 `{}`。
- `answers`（r2・r3・r4）: `json(shared:gate-answers.schema.json): 承認ノードの人の答え {start, before_fix}（始めの承認ノードと修正前の承認ノード。どちらも {decision, text?, asked?, pushed?} か null）。空のオブジェクトは答えが無い`。既定 `{}`。
- `request`（r2・r3・r4）: `file: 依頼のファイル（工場の依頼の JSON。r2 は本文の名指しの節を、r3・r4 は欄 answers を読む）。空は依頼のファイルが無い`。既定 `""`。
- `changed`（r2・r4）: `json(shared:fix-marks.schema.json): 修正の印（修正の出力の changed。真偽の欄と前提のずれの申告の文 premise_drift_note）。空のオブジェクトは渡されていない`。既定 `{}`。
- `pushes`（r3・r4）: `json(shared:pushes.schema.json): 無人の run が判定の保留の問いに採った推しの文の配列（「問い <key>: <推し>」）。空の配列は無い`。既定 `[]`。
- `decisions`（r3・r4）: `file: 先行議論の突合の素材（prior-decisions の block の出力 material の先。material.json。欄 reply.settled を読む）。空は突合が無い`。既定 `""`。

今との違い: 今は 25 の入力（始めの記録の pointer `start` を含む）を eyes の 1 つの YAML が受け、`prep.py` が始めの記録から差分の根・方針の写し・言語・依頼のファイル・修正前の HEAD を、判定の隣から問いの台帳と推しを読んでいた。block は始めの記録を受けない（README の 4.2・4.3）。読んでいた物は、block ごとに要る物だけを port にした。

### 0.3 共通の出力

4 つの block の `returns:` は `finish`、`outcome_field: ok`。どの block も次の欄を持ち、block ごとの欄を足す（各設計書の 1.2）:

- `ok`: boolean。`status` が `failed` でないか。目の判定が `pass` かどうかではない（block の仕事が最後まで回ったか。README の 13 節）。変更を通してよいかは eyes のまとめが `verdict` から決める（0.11）。
- `status`: `ran`（役の返答を読んで判定の行を組んだ）・`skipped`（役を起こさずに機械が判定の行を決めた。r2 だけ。r2.md の 1.2）・`failed`（入力が読めない・役の返答の記録が無い・判定の語が約束の外）。
- `reason`: 日本語の 1 行。`ran` と `skipped` は空。`failed` は訳（読めなかった port、落ちた筋）。
- `verdict`: 判定の行 `{status, reason}`。どの道でも在る（`failed` の時は `unverifiable` と、落ちた訳の `reason`。0.9）。`reason` は最後の承認ノードと報告にそのまま載る日本語か、役が `{lang}` で書いた字。
- `questions`: 人に回す問いの行（字の配列）。r4 だけが行を持ち、r1〜r3 はいつも `[]`（README の 8.4 の出力の名を 4 つで揃え、eyes のまとめが同じ欄を読む）。
- `report`: 報告の節「独立の目」に載せる日本語の行の配列。頭の 1 行はどの block も `<R の名>: <status>（<reason の 1 行>）`（今の `runreport._eye_lines` の行の形。`R1` などの名は今の `name.upper()` と同じ字）。続く行は各設計書の report の節。

### 0.4 共通の node の形

1. `intake`（script `intake.py`。`mutates_checkout: false`）: port を `os.environ.get("INPUTS_<名>")` の字のままで読み、`ports` の form の口に渡す。place の中のこの block のファイル（`src/files.py` が名を持つ物と `<node-id>-prompt-*.md`・`<node-id>-system-*.md`）を名で引いて消す（place は消さない。README の 13 章）。累積差分を取り（0.5 の `take_diff`）、`intake.json` に port の値・差分の控え・役を起こすかを書く。返り `{due, reason}`（r2 だけ `{compare, premise, reason}`）。読めない port が在れば `due: false` と、どの port かを頭に付けた訳（「入力 <名>: <訳>」。world の 9.1 の 3 と同じ）。差分が空・取れないことでは止めない（今の `test_empty_diff_points_at_the_reason`・`test_untaken_diff_is_unmeasured_not_zero`。訳は差分の代わりのファイルに書き、役はそれを読む）。
2. 役ごとに `<役>-prep`（script）→ `<役>`（AI）→ `<役>-save`（script）。prep は `prompt.emit(<役>, values, when, prompt.round_of(<役>))` だけで指示を組み、`{prompt}`（system prompt を持つ役は `{prompt, system}`）を返す。save は `with: {name: <役>, reply: $<役>.output}` を受け、返答をそのまま place の `<役>.json` に書いて `{saved: true}` を返す（今の `save_reply.py` と `eye_verdict.py` の書く半分）。r1〜r3 は輪を持たない（9 節の 2）。r4 は今と同じ受け付けの輪を持つ（r4.md の 1.3）。
3. `finish`（script `finish.py`。`trigger_rule: all_done`）: `with:` を持たず、place の `intake.json` と `<役>.json` を読んで出力を組む（今の `verdict.py` の形。落ちた node への `with:` は Archon が誤りで止める〔`dag-executor.ts` の producer-failed の照らし〕ので、返った役だけが書いたファイルで読む。今の E56）。`finish.json` にも書く。落ちない: 中の誤りは全部捕まえ、`ok: false`・`status: failed`・`verdict: {status: unverifiable, reason: "出口が落ちた: <型>: <文>"}`・`questions: []`・block ごとの欄は空か null・`report` は頭の 1 行だけ、を返す（今の `verdict.py` の `fallen`。NaN と Infinity は `allow_nan=False` で落ちた返りにする今の形も写す）。

script の node はどれも `runtime: uv`・`mutates_checkout: false`・uv の頭の宣言 4 行。script の名は `lib/` のモジュール・`.shared/*.py` の名と重ねない（README の 7.1 の 9。`intake`・`save`・`finish`・`<役>_prep`・`scope_accept` は重ならない）。YAML のコメントに埋めや sandbox の振る舞いを書かない（README の 1.3 の歩かせ 8）。

### 0.5 族の部品 `lib/eyekit.py`（r1 の PR が足す）

4 つの block が共に使う物だけを置く（憲法の 4）。中身はどれも今の `lib/eyeverdict.py` の関数の写しか、それを値で受ける形にした物（関数の docstring に写す元を書く）。標準ライブラリと KEEP の lib の部品だけを import する（`boardview`・`eyesbeside`・`fixbeside`・`startrec`・`judge_accept` は import しない）。Archon を知らない（`lib/AGENTS.md` の E3。除くパスの頭 `skip` は呼び手の script が `ports.RUNTIME_COPY_PREFIX` から渡す）。

- `take_diff(place, repo, base, skip, name, none_name) -> dict`: 累積差分 `{file, text, why, lines, changed, base, repo}`（`base` は引いた版の名、`repo` は作業ツリーの根。9 節の 9 の 3）。`fixboard.diff_file(repo, lambda: base or "HEAD", place, name, none_name, skip)` を呼び（作り直しの間は lib の `fixboard` を import する。10 節の 2）、`lines` は本文の行の数、`changed` は `changed_files(text)`。ファイルの名 `name`・`none_name` は block の `src/files.py` が渡す（README の 4.4）。今の `prep.py:78`。
- `changed_files(diff_text) -> list`: `changemap.split_diff` のファイルの並び（今の `eyeverdict.changed_files`）。
- `diff_values(diff) -> dict`: 断片 `eye-diff` の値 `{diff_file, changed_files, base, repo}`（ちょうどこの 4 つ。`prompt.render` は使われない値で落ちるので、ほかの値を足さない）。`changed_files` は `、` でつないだ字か、差分が無い時は `diff["why"]`（今の `prep.py:117`）。`base` は差分を引いた版の名（空なら `HEAD`）。
- `maps(repo) -> tuple`: 断片 `concept-map` の値と段落の真偽 `({concept_maps, map_tail}, found)`。`concepthome.tracked_names` と `pick_maps` で探す。`concept_maps` は見つかった地図の `- <パス>` を 1 行ずつ（`MAX_MAPS` を越えた分は `- and <n> more`）、`map_tail` は見つからない時の尾（木を読めなければ ` (the tree could not be read: <訳>)`、読めれば空の字）、`found` は地図が 1 つ以上在るか。字の組み方は plan.md の 2.3 の 13 と同じにする（plan の PR が先に字を決めていれば、その字に合わせる）。見出しと「先に Read で読め」「審査するファイルを含むフォルダの地図を正とする」「無ければ構造から探せ」の文は断片に在り、ここは持たない（今の `concepthome.section` の `MAP_NONE_HEAD`・`MAP_FOUND_HEAD` の文を md へ移した）。

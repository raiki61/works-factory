## 1 block の全体

### 1.1 役

累積差分と、目的・波及の一覧・定石の行・修正の印・修正前に通した行・直さずに残すと答えた事前審査の穴を材料に、差分が手を付けていない横断のリスクを探し、この変更が入れたか露呈させたリスクは `redesign-needed`、既に在って無関係なリスクは知らせるだけの行（`surfaced`）にして、判定の行を返す。棚卸しが発火すれば消えた能力を、方針とぶつかれば記録された方針の行を名指したぶつかりを、どちらも判定に数えずに返す。機械は、方針とのぶつかりが記録された方針の行を名指しているかを照らし、名指さない行を拒んで出し直させる（3 回目で諦め、名指さない行も人に聞く）。修正前に通した行と同じ物は問いから外し、外した行を通した印つきで控える。まとめた形では、R3 の答えが在ることも照らす。

### 1.6 つなぎ方（graph の側。block には書かない）

1. まとめた形を別の node にせず、`r4-scope` の指示の段落と、返答の必須でない欄 `r3` と、受け付けの照らしにした。根拠: 今の `eyes-one`・`eyes-one-fix` は `r4-scope`・`r4-scope-fix` と起こし方も輪も同じで、違いは指示（R3 の観点を足す）と型（`r3` を足す）だけ。node を 2 つ増やすと md も 2 本増え、R4 の観点の文を 2 本の md が持つ。持ち主の決め `eyes-by-reason` の組み方（R3 は R4 の会話にまとめる）は、port `coherence` で残る。
2. 輪の形を test-gate の block の `ci-loop` に揃えた（出し直しの prep を別の node にし、出し直しの周の筋書きは 1 回目の prep を差し替える）。根拠: 出し直しの役を 1 回目の役の会話の続きにする形と、輪の 2 周目を dry-run で照らす道が、作った block で 1 つに決まっている。
3. まとめた形の R3 の答えが無い時の拒否を受け付けに足した。根拠: 今は型の必須が同じ事をしていた（型に合わない返答は Archon が落とし `retry` が起こし直す）。型で必須にしない形にしたので、拒んで出し直させる（拒まれた欄だけを返せばよいので、今より安い）。
4. 人が通した行の控えを、ファイルの pointer でなく出力の値 `passes` で返す。根拠: 読み手（line の最後の承認ノードと report）が block の place のファイルの名と読み口（`eyeverdict.gate_pass_rows`）を知らずに済む（README の 4.4）。行の形は今の `gatemarks._keep` の形のまま。
5. 修正前に通した行を決める材料（聞いた項目 `asked` と修正前の答え）を port で受ける。根拠: 聞いた項目は line の修正前の承認ノードの事実で、block は承認ノードを持たない（README の 1.2 の U）。照らし（種類と推しの尾を外した本文）は今の `_human_passed` のまま block が持つ。
6. `src/steps.py` を足した（1.5 の一覧に無い）。根拠: r1 の block と同じく、入口・指示・受け付け・出口の組み立てを script から離して試験で直に呼べるようにする。`src/gate.py` の関数は私的な名の前置き `_` を外して公開の名にした（`human_passed`・`rows`）。
7. port の `description` は形だけを述べ、ほかの block の名と出どころを書かない（r1 の審査の決め）。1.2 の `purpose`・`ripple`・`world_rows`・`asked`・`declared` などの出どころの文は YAML に書かず、1.6 だけに残す。
8. `after`・`review` は `coherence` が真の時だけ読む（1.2）。偽の run は値を読まず、指示の `{after_section}` は空の字を渡す（段落に入らない）。読めない `after`・`review` が、まとめない run の R4 を止めない。
9. 2.3 の 17 の「受け付けの拒否の理由は、この会話の却下の節に在る」を、「却下の節、または出し直しを頼む指示」に直した。根拠: 通常の出し直しは 1 回目の指示の却下の節でなく、出し直しの役の指示（断片 `resubmit`）で届く。却下の節は resume の 1 周目だけ。
10. 筋書き `resubmit.stubs.yaml` は `r4-scope-accept` も差し替える（`{ok: true, done: true, ...}`）。根拠: test-gate の `base-resubmit` と同じ。差し替えないと本物の受け付けが前の答えの控え無しで拒み、輪が 2 周目に入る。受け付けの合わせは `tests/blocks/r4/` が見る。
11. `scope_accept.py` は `ports.run` で包み、中の誤りは `{ok: false, done: true, give_up: true}` を返す。根拠: 受け付けが落ちると輪の `until_bash` が読む欄が無く、輪が止まる。この返りは却下の控えに積まないので、`rolekit.given_up_reason` は諦めと読まない。そこで fallback は落ちた訳を place の `accept-crash.json`（`files.OWN_FILES` に入れ、入口が消す）に書き、finish はそれが在れば `verdict.reason` の尾に「（受け付けが落ちた: <訳>）」を足して `status: failed` にする（`r4-scope.json` を書いた後で落ちても `ran` にしない。前は `r4_accept.py` が落ちると R4 の筋が落ちた印になって見えていた。independent-design の block の `design-crash.json` と同じ形）。`until_bash` の変数名は `accepted`（`ci-loop` と同じ）。
12. 返答の控え `r4-scope.json` は受け付けが `accept_parsed` の前に書く（拒まれた回も、読めた最後の答えが残る）。`eyekit.read_reply` は `<名>.json` を引くので名は `R4_NODE`。

15. `R4_REJECT` の尾を「下の行を全部直して、返答を丸ごと出し直せ」から「下の行を全部直して、policy_conflicts を丸ごと（直さない行も含めて）出し直せ」に替えた（10 の 3 を閉じる）。根拠: 欄の単位で丸ごとと言えば、出し直しの断片 `resubmit` の決まり（返す欄だけを返し、返した欄は丸ごと置き換え）とも、resume の 1 周目の断片 `rejected`（全部を返す）とも食い違わない。test-gate の却下の文「素材の欄 material を丸ごと直して出し直せ」と同じ形。`lib/` は変えず、block の字だけで済む。

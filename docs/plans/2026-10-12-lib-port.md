# lib/ へ今の works の部品を移す計画（2026-10-12）

今の works の確かめの部品を、Archon を知らない助け手の層 `lib/` に移す。持ち主の決め `lib-port-as-is`（`docs/owner-decisions.md`）に従う。

## この計画の進め方

- この計画の全部（1A〜1G・2A・2C・2D・2F・3A）を **1 つの PR** で行う。項目ごとに 1 つ以上の commit を、波の順（波 1 → 波 2 → 波 3）に積む。
- 本文の「この issue」は「この項目」、「同じ波のほかの issue」は「同じ PR のほかの項目」と読む。波の「前提」は、同じ PR の前の波の項目の commit が在ることを言う。
- 2F の前提の #16（`tests/bin/gitkit.py`）は main に入っている（PR #21）。
- 次の物は、この計画では持ってこない（盤面か graphloops の規則に届く。ブロックの issue で扱う）: `impact`・`test_files`・`depth`・`red_check`・`baseline_red`・`features`・`entry_shape` の中心・`premises`・`purpose`・`policy`・`prcheck`・`class_query`・`test_freeze`・`plan_scope`・`give_up`・`groups`・`ruling`・`write_provenance`・`reads`・`protected`・`outcome`・`seal`・`green_cert`・`conflict`・`deltamarks`。`halt` は持ち込まない（`report-on-stop`）。`chain` は置き先が決まるまで外す（`one-launcher`）。

## このリポジトリと、この issue の位置

works-factory は、修正依頼を受けて確かめ済みの変更と報告を返す工場を、Archon（AI の工程を YAML で書いて回す道具）の上に作り直しているリポジトリ。前の形の「今の works」（公開リポジトリ raiki61/claude-plugins の works/。移す元の版は pack.json の works.commit = 2aa7c66cf7abe1fe09699ac2942d107123214168）の確かめの部品を、Archon を知らない助け手の層 lib/ に移している。どの能力をどこへ移すかの表は docs/design.md の「能力の棚卸し」（この issue に要る行は本文に写した）。

元のファイルは https://raw.githubusercontent.com/raiki61/claude-plugins/2aa7c66cf7abe1fe09699ac2942d107123214168/<パス> で読める（<パス> は本文の「元」の欄）。

読む物: 根の AGENTS.md（リポジトリの形・E14・E18）、lib/AGENTS.md（E3）、tests/AGENTS.md。

## 語

- 盤面（board）: 今の works が run の状態を置いた、自前の工程の実行器（graphloops の engine）の状態のファイルと、それを開く部品 board.py。新しい形では Archon が工程を回すので持ってこない。盤面の物（b.record・b.trace・b.work・b.state・b.output_of_round）を引数で受け取る関数も、盤面を知る関数。
- 写しの rules: 今の works が graphloops から写した工程の規則のファイル（graphloops/rules/review-loop.py など）。盤面が読み込む。持ってこない。
- ブロックの部品: 今の works の works/blk-*/（判定・修正などの段ごとの部品）と works/darkfactory/（段を並べた線）。新しい形の workflows/ に当たり、別の issue で作る。
- 波: 同時に出す issue の組。前の波が main に入ってから次の波を出す。

## 移し方

1. 元のファイルを、元のファイル名・元の中身のまま置く。置き場は、元の works/.shared/core/ を lib/ に、works/.shared/core/graphloops/engine/ を lib/graphloops/engine/ に読み替える。作り直さない。元のファイルが自分で sys.path に足す行（自分の置き場と graphloops）はそのまま残す。
2. 持ってこない物は、その関数・定数・クラスと、それにしか使わない import の行と、外した物にしか使われない名（lib に置くほかのファイルからも使われない物）を消すだけにし、ほかの行は変えない。
3. 盤面と Archon を知る部品は lib/ に持ってこない: board・script_io・scopes・flow_adapter・entry・adapter・tree_run・fixture・rolekit・seat・nodemeta・ticket・replycontract・graphmap・node_marker・leftovers・versions、graphloops/engine の board・advance・commands・validator・record・role_run・rules・declared、ブロックの部品。持ってくるファイルの中でこれらに届く物は、2 と同じに外す。本文の「外す物」は機械で出した見込みで、一覧の外でもこれらに届く物が見つかれば同じに外して PR に足す。
4. 層の試験（tests/layers/ の E3・E13・E14。照らす語は tests/layers/scan.py）に当たる字が、コメント・docstring・人に見せる文の中だけに在る時は、意味を変えずに言い換える（例: 「Archon の再開」→「実行基盤の再開」、/Users/x/ → /home/x/）。当たらない字は言い換えない。コードの値（環境変数の名・パス・表の値）に当たる時は言い換えず、その物を 2 と同じに外す。
5. 試験は、元の試験のファイルを元の名で lib/tests/ に置く。直すのは次だけ:
   - 頭の sys.path の行は消し、代わりに LIB = pathlib.Path(__file__).resolve().parents[1] と if str(LIB) not in sys.path: sys.path.append(str(LIB)) を置く。insert(0, ...) にしない（lib/ が頭に来ると lib/tests が根の tests を隠し、根からの unittest の見つけ方が壊れる）。
   - 元の木のパス ROOT / ".shared" / "core" / <名> は LIB / <名> に、ROOT / "dev" / "target-seed" は LIB.parent / "tests" / "e2e" / "target-seed" に読み替える。
   - 別の試験のモジュールを読む所は from lib.tests import <名>（または from lib.tests.<名> import ...）にする。
   - lib に無い物（外した関数・この issue で持ってこない部品・works/dev/・works/blk-*/・works/darkfactory/・works/docs/・works/tests/events/ などの物・今の works の写しの帳簿）を使う・読む・走らせる試験の関数とクラスは外し、それにしか使わない定数・助けの関数・import（gitkit・hermetic・linekit など試験の助けを含む）も外す。外す試験のための助けを tests/bin/ の物に書き換えて残さない。
6. PR の本文に次を並べる。commit に元のパスと版を書く。
   - ファイルごとの「元のパス → 置いた先」
   - 外した関数・定数・試験の名と理由（届いた部品の名）
   - 言い換えた行
   - 盤面の物を引数で受け取る関数の一覧（grep -nE '\bb\.(record|trace|work|state|output_of_round)' で出す。最後の掃除の材料）

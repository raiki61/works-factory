## 5 段の説明の字の出どころ

段の名・1 行の説明・受け渡す物の言葉・ノードの人の言葉を、どこに書くか。決めの縛りは 2 つ: 工場の中（`bin/`・`workflows/`・`lib/`）から見る道具へ頼らせない（E22・E25 の 1）。見るたびに LLM で書かせない（持ち主の言葉「毎回翻訳のためにLLMは使いたくないよ」と同じ訳。字が run ごとに揺れ、費用もかかる）。

- 出どころ S1 設計書から引く: `docs/design/line.md` に「段」の節を足し（段・1 行の説明・中のノード・受け渡す物の表）、見る道具がその節を字として読む。正本は 1 か所で、line を直す人が設計書と一緒に直す。弱い所: 設計書の書き手が、見る道具が読む形（表の列）を守らないと見る道具が読めない。設計書の形に、見る道具のための決まりが 1 つ増える。
- 出どころ S2 見る道具の中に書く: `viewer/stages.json`（段・説明・中のノードの id・受け渡す物の言葉）を置く。工場の中は何も変えない。4 章の照らしが、line のノードが足された時に赤にする。弱い所: 説明の字が設計書と 2 か所になる。照らしはノードの出入りしか見ないので、段の意味が変わった時の説明の古さは人が見る。
- 出どころ S3 line の YAML に書く: ノードの `description:` の頭に段の名を書く。工場の作りの正本の YAML に、見る道具のための字が入る（憲法の 1「YAML はつなぐだけ」に合わない）ので採らない。
- 出どころ S4 LLM に書かせる: 上の縛りで採らない。

ノードの人の言葉は、`workflows/line/src/nodenames.json`（block の `src/`。報告のための表）を見る道具が読むと、block の中の物への頼りになる（E22 の「block の `src/` を読んでよいのは同じ block の物と試験だけ」）ので読まない。S1 か S2 の表に、段の中の主なノードだけ（配線を除く）の言葉を書く。

推しは S2: 見る道具は工場の外の物で、工場の文書の形に見る道具の都合を持ち込まない方が、E25 の「工場の外に置く」に沿う。説明の字の古さは、表の行ごとに出どころの節（`docs/design/line.md` の 1.3 の番号）を持たせて、ページの箱から設計書へ辿れるようにして補う。持ち主に選んでもらう（9 章の問い 1）。

2. 何もしなかった出来事 → 採る（欄 4）。「出力が前と同じ」は、同じノードの道の前の起動の出力と字のまま同じ物。「空」は出力が無い・空の字・`{}`・`[]`。「後ろで誰も読まない」は、作りの読み（`src/shape.py`）のノードの欄（`with`・`when`・`refs` ほか）に `$<id>.output` の引きが同じ graph の中に 1 つも無く、graph の返り（`returns`）でもない物。工場は大きい物をファイルに置いて pointer で渡す（E5）ので、引きが無くても読まれていることが多い。ページは「出力の欄を引く先が無い」とだけ言う。
3. 繰り返しの周が、前の周と同じ所で落ちて回り直した物 → 採る（欄 3）。周の数と周ごとの費用、回り直しの訳として周の終わりの確かめ（`until_bash`。`run.checks` の終了の値）と、周の出力の欄を出す。「同じ所で落ちた」は、周ごとに落ちた手番の道（`status` が落ち）と確かめの値が前の周と同じ物。
4. 文脈の重なり → 採る（欄 5）。同じ system・同じ道具の一覧・同じ添え書きの片が入った会話の数と字の数（会話の字は `keep` で 1 つにした番号で比べられる）。同じファイルの読み直しは、道具の呼び出しの Read の `file_path` を、run の作業ツリーと run の置き場と run の写しの頭を外したパスで比べる。cache の読みと書きの割合は 4 分けの和から。

6. 頼みの例に無く足した物: 時間の内訳（欄 2。人の答え待ちは `wait` のノードの長さ）と、会話の往復ごとの積み上がり（欄 6。往復ごとの 4 分けの和）。積み上がりは、早い往復で入った大きな道具の結果が後の往復の全部に入り続けることを見せる。

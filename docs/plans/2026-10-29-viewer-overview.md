### 案 A 段の地図（見本 `a-map.html`）

## 5 段の説明の字の出どころ

段の名・1 行の説明・受け渡す物の言葉・ノードの人の言葉を、どこに書くか。決めの縛りは 2 つ: 工場の中（`bin/`・`workflows/`・`lib/`）から見る道具へ頼らせない（E22・E25 の 1）。見るたびに LLM で書かせない（持ち主の言葉「毎回翻訳のためにLLMは使いたくないよ」と同じ訳。字が run ごとに揺れ、費用もかかる）。

- 出どころ S1 設計書から引く: `docs/design/line.md` に「段」の節を足し（段・1 行の説明・中のノード・受け渡す物の表）、見る道具がその節を字として読む。正本は 1 か所で、line を直す人が設計書と一緒に直す。弱い所: 設計書の書き手が、見る道具が読む形（表の列）を守らないと見る道具が読めない。設計書の形に、見る道具のための決まりが 1 つ増える。
- 出どころ S2 見る道具の中に書く: `viewer/stages.json`（段・説明・中のノードの id・受け渡す物の言葉）を置く。工場の中は何も変えない。4 章の照らしが、line のノードが足された時に赤にする。弱い所: 説明の字が設計書と 2 か所になる。照らしはノードの出入りしか見ないので、段の意味が変わった時の説明の古さは人が見る。
- 出どころ S3 line の YAML に書く: ノードの `description:` の頭に段の名を書く。工場の作りの正本の YAML に、見る道具のための字が入る（憲法の 1「YAML はつなぐだけ」に合わない）ので採らない。

## 5.7 見本の見た目: Apple の見せ方から拾った型（受付 3b050e）

持ち主の言葉（2026-10-29）「あとは文字がごちゃごちゃしてるので、モダンなデザインとかで解決できる可能性があるね。アップルを参考にするといいかもしれない」。

### 5.7.1 拾った型と出どころ

出どころはどれも 2026-10-29 に読んだ一次情報。HIG は Apple の Human Interface Guidelines（`developer.apple.com/design/human-interface-guidelines/<頁>`）。

1. 画面の頭に主張を 1 つ、文で置く。細部は後ろ。HIG の charting-data「Summarize the main message of your chart」（Weather は「Chance of light rain in the next hour」を表の上に置く）。HIG の layout「place the most important items near the top」。
2. 細部は押すまで畳む。ただし主張に要る値は畳まない。HIG の layout「Use progressive disclosure」、disclosure-controls「hide details until they're relevant」、charting-data「Keep a chart simple, letting people choose when they want additional details」と「don't require interaction to reveal critical information」。畳みの札は中身を言う（disclosure-controls「Provide a descriptive label」）。
3. 字の段を少なくし、段は大きさと太さで分ける。HIG の typography「Adjust font weight, size, and color … to … visualize hierarchy」「Minimize the number of typefaces」「avoid light font weights」。見本は 4 段（40/600・22/600・15/400・12/400）と、本文の強め 15/600 だけにした。
4. 枠の線でなく、余白と面で組を分ける。HIG の layout「use negative space, container shapes, or separator lines」「Use consistent spacing」。見本は枠の線を外し、白い角丸の面と 20px の間を使った。
5. 色は 1 つ（青）を、押せる所と止まった所だけに使う。色だけで意味を持たせない（字を添える）。HIG の color「Avoid relying solely on color」、同じ頁の「Use color sparingly」「Prefer using color in places where it can help call attention to important information」。
6. 組ごとに「小見出し → 大きな数か短い主張 → 1 文 → 詳しく ＋」。apple.com の製品ページ（`apple.com/macbook-air/` の HTML の class）は、節ごとに `typography-section-label`（「Design」など 1 語）→ `typography-section-headline`（「Built to go places.」）→ `typography-section-intro`（1 文）と並べ、数の札（`typography-icon-card-headline`「Made with 55% recycled material」と 1 文の本文）の細部を押して開く板（modal）に置く。

### 6.5.2 行き来の口と戻り先

戻り先は 1 つだけ覚える（ページの中の値。ブラウザの戻るは使わない。ページは 1 枚で、VS Code の HTML ビューアの包みでは履歴を当てにできない）。どのタブも自分の姿（図の graph と寄せと板・流れと無駄のスクロール）を持ち続けるので、戻るはタブを替えてスクロールを戻すだけで済む。戻る札は、移った先の頭（図なら道しるべの頭、流れなら地図の上）に「← <元の画面>へ戻る」と 1 つだけ出し、押すと消える。別の口で移れば、戻り先はその口の元に替わる。

1. A の段の箱 → 図: line の図を開き、その段のノードを強めてほかを薄くし、強めた所が画面に入る大きさに寄せる。道しるべは「← 流れへ戻る · ⌂ line · 段 4 計画 · 説明 … · × 段の強めを外す」。再生の位置は変えない。line の図を描き直す（別の graph へ移る）と強めは外れる。
2. 道しるべの段の札（図 → A）: 「⌂ line」のすぐ後に、今見ている graph が属する段を青い札で出す。段は道しるべの 2 段目（line の中で今の graph へ入る include・`workflow:` のノード）から段の表で引く（例「⌂ line · 段 4 計画 › plan-review（ノード plan-review-run）」）。line そのものを見ている時は、段を強めている時だけ出す。札を押すと流れの地図のその段へ移る（戻り先は図）。段を道しるべの段（graph の道）の 1 つにはしない。段は graph ではないので、道しるべの段にすると「押すとその graph へ戻る」という #906 の道しるべの決まりと合わなくなる。
3. 図のノード → A: 板の頭（何をする物かの 1 行と、名と種類の下）に「段 4 計画 · 流れの地図で見る →」。段の引き方は 2 と同じ。一覧から開いて line から辿れない graph（#906 の「辿れない」）には出さない。
4. D の行 → 図と「LLM に入った物」: 行ごとに口を並べる。
   - 「会話を見る」: 再生の位置をその手番の終わりの歩へ移す（#906 の `go` をそのまま使う）。図はその手番の graph へ移ってノードを真ん中に寄せ、板はその出来事を開き、板の中を「LLM に入った物」の頭まで送る。
   - 大きな道具の結果（欄 6）の「その結果を見る」: 上と同じに移ったうえで、「LLM に入った物」の並びの中のその結果の片を開いて枠で目立たせ、そこまで送る。#906 の `contextView` には片を外から開く口が無いので、開く片を渡す引数を 1 つ足す（見本は字数の一番大きい「道具の結果」の片を探して開いた）。
   - 「図の札へ」: 再生の位置を変えずに、図のその所を開いて板を出す（何をする物かを見るだけの時）。
   - 「段 n へ（流れ）」: 流れの地図のその段へ（6 章の口）。
   - 周の行（欄 3）はその周の最初の手番へ、文脈の重なりの行（欄 5）は会話が何本もあるので、行を開いた中に会話ごとの「会話を見る」を並べる。
5. E の 1 行 → 図の札と板: 1 行は図の札の 2 行目（今の「種類 · script の名」の所）に出し、種類と script の名は板の頭へ下げる。1 行が出る所（D の行・A の段の中のノードの並び・再生の帯の今の 1 文）から押すと、4 の「図の札へ」と同じに移る。
- 戻り先のまとめ: 1・4・5 で図へ移った時は元の画面（流れか無駄の手がかり）の元のスクロールへ戻る。2・3 で流れへ移った時は図へ戻る（図の姿はタブが持ち続けている）。4 で再生の位置を移した後に戻っても、位置は移した所のまま（流れの縦の線もそこに居る）。

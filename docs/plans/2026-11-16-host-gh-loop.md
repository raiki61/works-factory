# run の中の gh の口が利用者の gh の包みと呼び合う不具合の直し（2026-11-16）

出典: guided-resolver の窓口からの頼み（受付 20261116-030308-a7be75）。

## 1. 起きたこと

- 殻（`bin/_lib/launcher.py`）は run ごとに、利用者のログインを継ぐ gh の口（`bin/_lib/hostgh.py` の `write` が run の家の `host-gh/<hash>/gh` に書く）を Archon の子の PATH の頭に置く。口は利用者の PATH で最初に見つかった gh を `exec` する。
- 利用者の gh が包み（PATH から自分の置き場だけを抜いて本物の gh を探す物）だと、口は子の PATH のまま包みを起こすので、包みが探す PATH の頭に口が残る。包みは口を本物と取り違えて口を起こし、口は包みを起こし、呼び合いが止まらない。
- run 2f08b32f・5196f102（版 PIN 7bbe3e43）の start の段の `gh issue view` の中の `gh auth token -u …` が、2 時間 21 分 CPU を使って回り続けた。利用者の側は包みに呼び返しを抜く仕掛け（GH_ROUTE_SKIP）を足して直した。

## 2. 直し

1. 口は、本物を探した利用者の PATH（口の置き場と読むだけの口 `bin/_lib/no-post-bin/` を除いた物）を口の中に書き、それに戻してから利用者の gh を起こす。包みから見える PATH は利用者のシェルと同じになり、口は見えない。HOME・GH_CONFIG_DIR をすでに利用者の値へ戻しているのと同じ向き。
2. 口は自分の先の gh に印（env `WORKS_FACTORY_GH_SHIM_ACTIVE`）を立てる。印の在る env で口が起きたら、先の gh が別の道（env に控えた PATH など）で口を呼び返しているので、訳の 1 行を出して終了の値 1 で止まる。期限ではなく形で止めるので、持ち主の決め `no-timeouts` に当たらない。
3. 試験は `tests/bin/test_hostgh.py` の `test_users_wrapper_does_not_call_back_into_the_shim`（1 の直し。包みの偽物で、直す前は呼び合いが偽物の上限で 99 になる）と `test_call_back_into_the_shim_stops_at_once`（2 の直し。直す前は止まらずに試験の子の上限 10 秒で落ちる）。どちらも直しを外すと落ちることを確かめた。

E14（普通の利用者の環境）: 包みを使わない利用者には、gh の子（git・拡張・資格の helper）が見る PATH が、殻が組んだ子の PATH から利用者の PATH に替わるだけ。Archon の子の PATH の頭に足した物（gh の口・bun の置き場・forge のプラグイン）は gh も gh の子も使わない。

## 3. E11 の 3 つ

1. Archon が持っているか: 持っていない。Archon は script のノードに過程の env をそのまま渡し、gh の解決を持たない（`docs/design/archon.md` の「対象のコマンドの環境と準備」・`docs/polyfills.md` の役の PATH の頭の項）。
2. ASF が持っているか: 持っていない。ASF は利用者の環境のまま gh を打ち、HOME を隔離しないので口が要らない。
3. 本当に要るか: 新しい仕組みは足さず、在る口（`hostgh.write`）の中身を直すだけ。

## 4. 回り続ける子を見つける手段（頼みの 2 つ目）

- この不具合の型（gh の口を通る呼び合い）は、2 の印で形として止まるので、期限も見張りも要らない。
- 段を問わずに「進まない段を知らせる」見張りは、run の外に常駐する物か、Archon の段の進みを読む新しい部品になる。E10 で持ち主の決めが先に要る。`no-timeouts` は期限で止めることを退けた決めで、止めずに知らせるだけの見張りを許すかは決めていない。
- だから今回は足さず、持ち主の選びとして返す（納品の残った疑問）。足す時の形の案: 殻が `workflow run` の子を待つ間、run の記録の更新が N 分止まったら標準エラーに 1 行を出す（止めない）。N は数の上限になるので、憲法の 6（数で縛らない）との関係も持ち主に聞く。

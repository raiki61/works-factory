How to read the diffs: from the second pass on, the material shows each open item's diff since the earlier pass and its ripple list, not the whole item. The review in the earlier pass already read each item whole, and the only holes it left that need an answer are the earlier blocks and owed suggests (the section "Previous passes"). In this pass, look only at (1) whether those earlier holes are gone (if gone, put the key in `resolved`, the answer's list of earlier keys that are gone; if they remain, raise them again in `faces` with the same key, the same severity, and the same `reach`, the fields "How to write the holes" defines) and (2) the new holes that the diff and the ripple list make. A diff row is `<mark> <place>: <sentence>`: `-` is a sentence only in the earlier pass, and `+` is a sentence added in this pass (unchanged sentences are not shown). A line `contract fields changed: …` names the contract fields of the item that changed (the whole item is not shown). Do not look again at places outside the diff to search for new holes. Do not change the rule of severity (block or suggest) or the rule of `reach`: if you relabel a block that had a central value to `peripheral`, write in the first sentence of `why` why it no longer meets the earlier definition. A block whose harm one test can guard may be moved down to `peripheral` this way with `guard` (its severity stays `block`) (see the list "How the checks above read the plan" in this prompt).

When the material has the section "Overlaps and other items' scope": if the diff of an open item disagrees with the units, the scope, or the files touched of the other items listed there (closed items included), raise that disagreement as a hole too. The other items' plan text is not shown there; read the files in the working tree if you need them.

How to read a ripple list: its uncovered hits are the hits that none of the item's writable paths (`allowed_paths`), acceptance tests (`tests`), or rewritten tests (`rewrite_tests`) cover. Anything the fix will touch (callers to align, tests that assert a literal value to rewrite) must be in that item's `allowed_paths` or `rewrite_tests` now: what is in the plan can be written during the fix without asking about scope, and anything outside it can only be written after the fixer asks the plan role and gets permission. Check every uncovered hit: the item covers it, it has no effect, or it is a hole. A name marked `common name: only the count` has hits in so many files that its callers are not all listed: read the code and decide whether the fix touches them. When the list says `ripple list missing: …` (the machine could not build it), look up the callers and the tests yourself.

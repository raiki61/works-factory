# Fixing (the writer's job)

You are the TDD loop's closing writer. You read the judgment, cut into root units (unit) and passed by the acceptance; the TDD loop has already fixed the units you owe a fix on the working tree, test first, and the machine confirmed each test's red-to-green. Do not fix them again: write the answer for those units (one row in `changes` per unit, and the fields for the whole round), as the result of the TDD loop in "What to read" says. The machine (the shared board) accepts your answer and recounts before and after the fix with the judgment's way of counting.

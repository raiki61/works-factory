To read GitHub pull requests, issues, and repositories, run the read-only command `works-gh` by its bare name, as a single command (for example `works-gh pr view 12 -R OWNER/REPO`). Only these forms pass: `works-gh pr list -R <OWNER/REPO>`, `works-gh pr view <number or branch> -R <OWNER/REPO>`, `works-gh pr diff <number or branch> -R <OWNER/REPO>`, `works-gh issue list -R <OWNER/REPO>`, `works-gh issue view <number> -R <OWNER/REPO>`, `works-gh repo view <OWNER/REPO>`, and `works-gh api [--paginate] repos/<OWNER>/<REPO>/pulls/<number>/comments` (the line comments of a pull request), and only this form runs outside the sandbox. If you call it as `gh`, through a variable that holds its path, with a pipe, `&&`, `;`, or a command substitution, or with a variable assignment in front of it, it runs inside the sandbox and cannot reach the network. Read the target repository's issues with `works-gh`, not WebFetch, because WebFetch cannot read a private repository. Read searches and other web pages with WebFetch and WebSearch. The wrapper stops any gh command that writes.

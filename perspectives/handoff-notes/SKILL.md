# Notes handed over to the next pass

**Core rule: the next pass at the same work starts with nothing. Write it what you read, what you kept, what you set aside, and what is open — all four, even if a list is empty.**

## Pitfalls (read first)

- **Set-aside options are the most easily lost.** Without them the next pass tries the same rejected path again. Record not only alternatives to the path you chose but also other ways to fix or to write that you considered and dropped, each with why.
- **Keep the notes apart from the work itself.** They are not part of the body or the plan; they are for whoever does the next pass.
- **When picking up, do not resurrect what was set aside** unless the rejection reasons (why the last pass's result was refused) or the review findings (what a reviewer pointed out in it) ask for it.

## Steps

Read "What to write" when a pass ends, and "When picking up" when you start a pass that earlier passes left notes for.

### What to write

- **Read**: the places you read (path, lines) and why you read them.
- **Kept**: what you decided to keep, and why, as sentences.
- **Set aside**: each option you set aside, and why.
- **Open**: what is not decided yet, as sentences.

### When picking up

Read every earlier pass's notes, from the oldest. Read again from the places in "read", keep what is in "kept", do not bring back "set aside" options unless the new feedback asks for them, and check "open" against the rejection reasons and the review findings. A pass with no notes, or whose notes cannot be read, is passed over: go on without them.

## Done when

- When ending a pass: all four lists are written, even the empty ones, apart from the body and the plan.
- When picking up: every earlier pass's notes were read, oldest first, and no set-aside option came back without the new feedback asking for it.

## How to report

The four lists, kept apart from the work: read (path, lines, why), kept (what and why), set aside (each option and why), open (what is not decided).

## Example

Input: a pass rewrote a setup guide's install section; a reviewer may ask for changes.

Reply:

- Read: the install section, lines 10–40, to see what it promised; the release notes, lines 1–15, for the current version.
- Kept: one numbered list of steps, because the old text mixed steps and notes.
- Set aside: a table of platforms — too wide to read in a terminal; splitting the guide into two files — the request asked for one section.
- Open: whether the uninstall steps belong in the same section.

## Works well with

- A way of answering a reviewer's findings one by one when the work is picked up again.

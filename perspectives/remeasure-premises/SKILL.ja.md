# 何かを積む前に、依頼の前提を測り直す

**芯の決まり: 主張は、この作業ツリーで測った値か、ファイルを名指す事実になって、走らせた命令とその出力を見せられた時だけ前提になる。それ以外は仮説。**

訳: 後に来る人は、この前提をそのまま取って読む。ここで間違った事実を渡すと、その上に積む判断と修正が全部外れ、間違った前提は後の判断もすり抜ける。

## 落とし穴（先に読む）

- **依頼した人の測りを、書いたままには信じない。** 別の版・別の作業ツリー・もう無いパスで測った物かもしれない。ここで測り直し、合わなければ、測った値と依頼の値との違いを書く。
  - 本当に在った例: 「本文は最大で約 4MB」の 4MB は、同じ変更が消したパスで測った物だった。本当の大きさは 5,411 バイトで、その間違った前提の上に 5 周ぶんの仕事が積まれた。
- **確かめ直し無しに信じられるのは「測った」だけ。** 後の役は、ほかの事は全部一から疑うが、「測った」と印の付いた前提だけは疑わない。だから間違った「測った」はそのまま前提として使われ、その上に判断が積まれる。
  - 本当に在った例: 「リポジトリに CI の定義が無い」が測ったとして記録されたが、CI のワークフローのファイルは在った。同じ run のほかの仕事がその前提で書かれても、正されなかった。
- **覚え・前の測り・一般論を前提として渡さない。**
- **「無い」には、どこを見たかが要る。** 見た所と命令を貼る。空の一覧や空の検索も出力。
- **作業ツリーを 1 文字も変えず、履歴も動かさない。** 変えると、測った物が後の修正の差分に混ざる。出力は作業ツリーの外に書く。間違って何か作ったら、終える前に消すか、書き換えた追跡中のファイルを元に戻す。

## 手順

1. 依頼の各行から、数・大きさ・件数・在る／無い・「X が届きうる」・「X が赤くなる」の主張を全部拾う——言っている事・挙げた仕組み・空振りになる条件のどれからも。
2. 測った値を持つ行には、少なくとも 1 つの縛りを書き、その行の所を字のまま入れる。
3. 主張をそれぞれ、この作業ツリーで測る（数える・大きさ・一覧・履歴・試験を回すなど）。
4. ファイルを名指す事実にも、それを示す命令（一覧・行番号付きの検索）が要る。走らせて出力を付ける。
5. どの縛りにも、どう測ったかを書く。
6. 縛りごとに印を付ける:
   - **測った**: 走らせた命令とその出力を見せられる（長ければ要る行だけ。命令の行は `$ ` で始める）。
   - **仮説**: 見せられない——例えば本番の入力や対象の外の物。所と、なぜ測れないかを書く。依頼した人の値を「測った」として写さない。
7. 測った物が依頼の行の主張や前提と食い違う時は、どの行と食い違うかを書く。
8. 依頼に測る主張が無ければ、一覧は空でよい。

対象の名が要るので走らせなかった調べは、仮説として渡し、何を確かめたかったかと、走らせなかったことを書く。その印が人へ回す合図になる。

一緒に使うと良いもの: Web の検索など外のサービスへ送る問い合わせに、相手のリポジトリの名やパスを入れない観点（非公開かもしれない名が外の記録に残らないようにする）。

# 人が置いた前提から設計する

**芯の決まり: 仕事の途中の人の答えは、目的の前の書き方に勝つ。答えが変えた後の目的に照らして設計する。**

ここで使う語:

- **対象**: 設計の向かう先のシステム（リポジトリ）。
- **依頼**: 変更を求める人の依頼で、設計の出発点になる文。
- **承認の所**: 仕事の途中で、人が問いに答えるまで止まる所。
- **地図の文書**: 対象の根に在り、全体の構造を書く文書（アーキテクチャの概観・部品とそのつながりの一覧）。

## 落とし穴（先に読む）

- **答えを先に読む。** ほかの材料より前に。
- **取り下げられた要件は、動かせない約束ではない。** 答えが目的や前の要件を取り下げた・変えたなら、変わった後の要件を前提にする。
- **取り下げた要件を残しただけでは、前提を破ったと数えない。** 設計が取り下げた要件をまだ持っていても、それだけでは違いでも、前提の破れでもない。答えが変えた後の目的と比べる。
- **無い文書は、空の文書ではない。** 依頼の文が読めなかったなら、依頼が名指す設計の文書の節は渡されていない。無い事を、依頼が何も名指していないと取らない。

## 前提として読む物

1. **仕事の途中で人が答えた事**（承認の所で）。
2. **依頼が名指す設計の文書の節**（依頼を固めた時の版）。目的と同じく、依頼の一部として読む。
3. **対象の根に在る地図の文書。** 依頼が名指していなくても、設計を、システムに既に在る物から始める: 信頼の根（資格と信頼が始まる所）・外との通い道（システムが外と話す所）・守っている物。

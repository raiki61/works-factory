# 単位ごとに試験先行で直す: 赤、緑、整理

**芯の決まり: 1 単位ずつ、試験 → 直し → 整理。赤か緑かは試験を走らせた結果が言う物で、自分が言う物ではない。試験・依頼・コードを曲げないと緑にならないなら、止まって食い違いを宣言する。**

下で使う言葉:

- **単位**: 根の原因 1 つの欠陥。見た目の違う症状が同じ原因から出ているなら 1 つの単位で、直す時はその原因と同じ形の箇所を全部直す。単位の分け方は、前に出した欠陥の判定が決める。
- **判定**: 欠陥が何か・なぜか・どこから来たかの見立てと、同じ形の箇所を全部見つけて数える照らし（検索の形や確かめ。以下「欠陥を数える照らし」）。
- **計画**: 合意した修正の計画（在れば）。項目ごとに、触ってよい範囲と、受け入れの試験（その項目が直ったと言うために、決めておいた名前で書いて赤から緑にする試験）や書き替える既存の試験を名指す。計画が無ければ、判定が直す物の拠り所になる。
- **依頼**: 人が直してほしいと頼んだ物の文。
- 赤・緑・整理は、red（落ちる）・green（通る）・refactor（緑のまま整える）のこと。

## 落とし穴（先に読む）

- **赤は試験自身の確かめの失敗。** 読み込み・ビルド・準備の失敗は赤ではなく、走らなかった試験も赤ではない。もう通る試験や飛ばされた試験も赤ではない。
- **思った訳で赤。** 失敗の字を試験の出力のまま写し、思った訳（機能が無い。打ち間違いではない）で落ちたことを言う。写しを作り上げない。
- **直す間と整理の間、試験は凍っている。** 赤の段で変えた試験の側の物（期待の出力・試験の補助・試験のデータ）も、名前やフォルダに依らず一緒に凍る。試験の誤りに気づいても、その時は直さず書き留める。変えないと進めないなら、食い違いを宣言する。
- **書き替えると言われた物以外の、既存の試験の中身を触らない。** import・助けの関数・新しい試験は良い。
- **今の単位の間、後の単位を触らない。** 前の単位の直しを戻したり、やり直したりしない。
- **試験は、前に走った形で回す。** 直す前に試験を回した形が分かっているなら、その形で（要る所に絞って）回し、環境やコマンドを探し回らない。
- **戻ってきた指摘を直す後の回では**、前の回が赤から緑にした受け入れの試験（凍っている）を、計画がこの単位に並べていても使い回さない。戻ってきた指摘には、今の作業ツリーで落ちる新しい試験を書く。

## 1. 単位を分ける

どの単位も 1 回ずつ分ける:

- **試験先行**: リポジトリの試験の束の中に、直す前に落ち直した後に通る試験を書ける。
- **直に直す**: そういう試験を先に書けない（文書・指示・覚え書き・設定だけの直しなど）。訳を書く。

試験を書いている途中で、やはり先に試験を書けないと分かった単位は、訳を添えて「直に直す」へ回す。ただし計画がもう受け入れの試験を決めている単位は回さず、食い違いを宣言する。

## 2. 赤: 欠陥を再現し、今落ちる試験を書く

- 読み込みやビルドで落ちず、試験の中の確かめで落ちる形に書く。
- これから足す名が無いためにそう書けない時だけ、試験のファイルの外に最小の仮の実装を足す。形だけで、確かめに落ちる値を返す物。本物は直しの段で置き換える。
- 試験そのものが間違っていたら、試験を直して走らせ直す。
- 計画がこの単位に受け入れの試験や書き替える既存の試験を名指していたら、それを書く・書き替え、今のコードで落ちるようにする。計画が書いた落ち方は、思った落ち方としてだけ読む。計画どおりに書いて落ちない、または違う落ち方をするなら、試験を曲げずに食い違いを宣言する。
- 前に通っていた試験は、今も通るままにする。

## 3. 緑: 今の単位だけを直す

- 今の単位（欠陥と同じ形の全部の箇所）を直し、それ以外は直さない。
- 凍った試験のファイルは変えない。
- 自分で試験を走らせ、赤が残っていたら直してから返す。
- 人が試験の全体を回すコマンドを渡していたら、名指した試験だけでなく、そのコマンドも緑にする。
- 緑の後に整えたい物（重なり・名前・要らなくなったコード）があれば、整理を宣言し、訳を書く。宣言が無ければ整理の段は来ない。

## 4. 整理: 宣言した物だけ

宣言した物を、緑のまま、試験のファイルを変えずに整える。整える物が残っていなければ、何も変えない。

## 一緒に直す単位

同じ計画の項目に在り、1 つのやり方を分け合う単位は、どの段でも今の単位と一緒に扱う。赤の段では項目の受け入れの試験を全部落とし、緑の段ではそれらの単位の直しを含めて通す。

## 食い違いの宣言（緑にするために曲げない）

どの段でも、試験・依頼・コードのどれかを曲げないと緑にならないなら、代わりに食い違いを宣言する。食い違う所を 2 つ以上名指し（`<path>:<line>` か行の範囲）、なぜ同時に成り立たないかを言い、どちらが正しいと思うかを言う: 依頼・試験・コード・分からない・欠陥を数える照らし（照らしが、正しく直した後の行にも当たってしまい、直しても数が減らない時。その時は、照らしが当たる直した後の正しい行を宣言に写し、照らしの方が間違っていると示す）。よくある場面:

- 計画が書いた単位と、欠陥の判定が食い違う。
- 誰も名指していない試験が壊れた。
- 名指した試験が赤にならない。
- 直しに、決めた範囲の外の物が要る。
- 欠陥を数える照らしが、直した行にも当たる。
- 直しに、渡されていない文脈が要る。

宣言した単位は、もう直さない。作業ツリーはその単位を始めた所に戻り、ほかの人が裁く。

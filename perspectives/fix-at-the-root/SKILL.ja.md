# 根本を閉じる直しを書く

**芯の決まり: 診断が名指した根本を、同じ形の在る所全部で、既に在るいちばん小さい物で閉じる。直した人にしか分からない物を対象に残さない。**

## 落とし穴（先に読む）

- **指摘を 1 つずつ潰さない。** 指摘の一覧は症状で、根本は診断の訳と、欠陥がどこから来たかの見立てが名指す。そこを閉じる。
- **診断が今直すとした物を後に回さない。** 診断が止めると印を付けた欠陥と、今直すとした小さな指摘は全部直し、自分の判断で後へ回さない。診断の前提や直し方に疑いが残っても、方針の中での一番の直しを入れ（症状しか閉じないならそう言う）、疑いは異議として書き残す。直さずに残してよいのは、人の答えが無いと直し方を決められない欠陥だけで、それは申し出る。
- **名指された 1 か所で止まらない。** 診断が持つ同じ形を探す問い合わせを使い（無ければ書き）、全部の箇所を見つける。
- **迷いを隠さない。** 自信の無い場合を、既定値・誤りを飲み込む catch・黙った代わりの道で処理済みに見せない。仕上がった直しの代わりに、TODO・FIXME・空の実装・スタブ・コメントにした古いコードを最後の差分に残さない（赤の段が足し、後の段が本物に置き換える最小のスタブは最後の差分に無いので別）。人か依頼にしか決められない迷いは、隠さずに申し出る。
- **直す過程の言葉を対象に書かない。** コードの注・docstring・文書・テストの名・識別子・文字列・ファイルの名・拒みの文は、直し方を見ていない人がマージの後に読む。直しを作った過程の言葉（その段や役の名、その過程が仕事のひとまとまりや 1 回の通しを呼ぶ語。たとえば「単位」「この周」）も、作った時の事情（「ここでは測れなかった」「この作業ツリーには無い」）も書かない。対象に書く理由は、対象のコードと文書だけから読み手が辿れる物にする。「指示がそう言った」「審査が求めた」「定石がそう言う」はその理由にならない。
- **何も変えずに「済んだ」と言わない。**
- **前の試みの後に赤くなった試験は、その試みを指す。** 同じ仕事の前の試みの後に CI が試験を赤くしたなら、前の試みの直しがその試験を赤くしたと見て、同じ試験をまた赤くしない直しを書く。これとは別に、答えの形を決まった規則で受けるか断るかする自動の検査が前の試みで何かを断っていたら、それは同じ所でまた断られないための注意であって、直す欠陥ではない。
- **ライブラリの API は文書で確かめる。** 変更がライブラリの関数の形・引数・使い方に頼る時は、対象に入っている版の文書（入っているコードから読む）と、ライブラリの持ち主の公式の文書（できれば同じ版の物）で確かめる。手元に無ければ公式の文書を自分で取りに行く。

## 手順

「直し方」と「直さずに止まる時」はどの直しでも読む。「事前審査を受けた計画に従う時」「仕事を手伝いに分けた時」「直しが問題つきで戻った時」は、その場面でだけ読む。

### 直し方

1. **出来合いを先に。** 書く前に、使っている依存（基盤の標準ライブラリ・版管理・プロジェクトが既に回している道具）か、よく知られたオープンソースが同じことを既にしていないかを確かめ、していればそれを使う。診断が何も作らない処方（取り下げる・消す・既に在る仕組み 1 つで済ます）を挙げていれば、それを先に採る。要る以上に複雑にせず、在る仕組みを作り直さない。
2. **根本、それから全部の箇所。** 根本を直し、同じ形の箇所を全部直す。
3. **行き止まりの道は注で済まさず閉じる。** 足したのに何も呼ばず何も届かない入口や設定は、呼び手をつなぐか、届かない物を消して直す。注を書いて済ませない。
4. **要らなくなった物は同じ変更で消す。** 書いた後、自分の差分を見て、消した物・変えた物のせいで最後の呼び手や参照を失った引数・変数・関数・export・import・型を探して消す。どの呼び手も今は同じ値を入れる引数やオプションは、定義に畳んで消す。ただし公開の API には及ばない（リポジトリの中に呼び手が残らないことは、外に残らないことを示さない）。畳むと変えてはいけないテストを変えることになる引数は畳まず残す。
5. **古い振る舞いを述べる文を全部直す。** 振る舞いを変えたら、注・docstring・テストの名・拒みの文・文書から、変える前の振る舞いを述べたままの文を探し、直すか消す。走らせた検索は証拠として残す。テストの名・文・名前で言えることに新しい注を足さない。注が言うのは「なぜ」だけ。
6. **仕組みを足す前に外を見る。** 仕組みを足す直しや形を変える直しは、書く前に、対象の外（Web などの外のサービス）で一次情報（標準・よく知られたオープンソース・公式の文書）を探し、世の中が同じ問題をどう解くかを確かめ、問題・実際に開いた出典・採るか（そのまま採る・変えて採る・当たらない・見つからない〔その時は何をどう探したか〕）を残す。自前で作るなら、世の中の解が無い・使えない訳を出典つきで書く。
7. **2 つ以上の直しが同じファイルに触れたら**、触れた所ごとに比べる: 片方が他方を要らなくしないか（なら 2 つのうち 1 つだけを当てる。当てるのは変更の小さい方）・当てる順で結果が変わらないか・組み合わせた時だけ生まれる状態が無いか。確かめたことと生まれる物を残す。

### 直さずに止まる時

- **直しが新しい仕組みに届くか、共有の面を広げると気づいたら、すぐ止まる**（新しいモジュール・型・設定の鍵・共通の入口。ほかの所も読む・呼ぶ物）。それは設計の仕事で、何も作らない案と比べていない仕組みを直しから出してはいけない。仕組みを足さない直しを入れ、その訳で「症状を閉じた」と印し、診断のやり直しを頼む。ほかの欠陥は直し続ける。
- **まだ開いている問いの上に作らない。** 答えの無い問いの出どころか、それに頼る欠陥は、その訳で残す。人が答えたら（人がいない時に、人の代わりに推奨の答えを採ったと記録された時も同じ）、また直す義務に戻る: 答えが選んだ案で直し、答えがその問いに触れていなければ、問いが推した案で直す。
- **診断の切り方に異論があっても、自分で切り直さない。** 欠陥のまとめ方・根本の読み方・それぞれをどうすると決めたかへの異論として残し、やり直す診断が読むようにして、今回は診断のとおりに直す。人への問いはその異論に書かない。
- **根本か症状かを口に出す。** 直しごとに、診断が名指した根本を閉じたのか、症状を閉じたのかを書く。症状なら、なぜ今そこで止めるかを書く。

### 事前審査を受けた計画に従う時

審査が挙げた穴と小さい案の全部に答える: 取り込んだ（どう取り込んだか）か、残す（なぜか。誤りの指摘なら、本物のコードのどこで誤りと言えるか）。残すと答えた止める穴は消えない。次の審査が止める穴としてまた挙げると思っておく。答えの中に「人に渡す」と書いても人には届かない。人が決める物を人が読む所に書く。

### 仕事を手伝いに分けた時

- 作業ツリーの差分は自分で確かめる。手伝いが何を変えたかの報告を信じない。
- 1 つの項目の審査役は、その項目に関わる所を見る。前の項目の直しそのものは見ないが、今の項目の直しがそれを壊すなら指摘する。
- 最後のやり直しの後も審査に指摘が残る項目も、直した物として、症状を閉じたと印し、残った指摘を訳にして報告する。直したと数えず申し出るのは、まったく直せない欠陥（人の答えが無いと直し方を決められない、または手伝いが文脈が足りない・行き詰まったと報告した物）だけ。

### 直しが問題つきで戻った時

- 一覧が挙げた問題を全部、まとめて直す。
- やり直すのは一覧が名指す項目だけ。ほかの直しはそのまま残す。

## 済んだと言える時

- 止めると印された欠陥と今直すとされた物が全部直っている。直していないのは、直し方に人の答えが要る物だけで、それは申し出てある。
- 名指された所だけでなく、同じ形の箇所を全部探して直した。
- 最後の差分に、仕上がった直しの代わりの物も、直す過程の言葉も無く、何かを本当に変えた。
- 古い振る舞いを述べた文を全部直すか消し、最後の呼び手を失った物を消した。
- 直しごとに根本か症状かを書き、症状ならそこで止める訳を書いた。
- 事前審査が在った時は、挙げた穴と案の全部に答えた。
- 作業ツリーの差分を、手伝いの報告でなく自分で確かめた。

## 返し方

直しごとに: 何を変えたか、根本か症状か（症状なら今そこで止める訳）、同じ形の箇所をいくつ直したか、走らせた検索（形を探す物と、古い振る舞いを述べた文を探す物）。仕組みを足す直しなら、問題・開いた出典・採るか（そのまま採る・変えて採る・当たらない・見つからない）。同じファイルを共にする直しなら、比べたことと生まれる物。そのうえで分けて: 直さなかった欠陥と訳、診断の切り方への異論、人が決める物（人が読む所に書く）。

## 例

入力: 診断が、今直す欠陥を 1 つ名指す——共有の日付の助け手が、読めない入力に今日の日付を返し、呼び手はそれを信じている。

返し:

- 根本を閉じた: 助け手は、読めない入力に既定値を返さず、誤りを上げるようにした。
- 同じ形: 助け手の名で検索して呼び手を 3 つ見つけ、3 つとも誤りを扱うようにした。
- もうどの呼び手も入れない既定の日付の引数を消した。
- 「今日に戻す」と書いていた助け手の doc コメントを直した。走らせた検索: 助け手の名・「戻す」。
- 直していない物: 無し。

## 一緒に使うと良いもの

- 外での検索を、対象の私的な名前を入れない言葉で書く見方（「直し方」の手順 6 で使う）。

# 残りかすを残さずに消す

**芯の決まり: 物とそれを縛る物を全部消し、使っていた所を直し、消えたことを、消えたことについてのテストでなく、木に無いことで示す。**

## 落とし穴（先に読む）

- **消す。別の振る舞いに書き換えない。** 消した物を使っていた残りのコードは、それを要らなくなるように直す。代わりに新しい振る舞いを与えない。
- **消した名前が無いことだけを確かめるテストを書かない。** 木の検索が確かめになる。
- **まだ触れられている名前は消えていない。** 呼び手・テスト・文書のどれかがまだ触れていれば、消し終えていない: 残りの触れる所を消すか、振る舞いが本当に変わったのなら、その変化を示すテストを名指す。

## 手順

### 消し方

1. 名指された名前とファイルを消す。
2. 消す物を縛るテストを、それと一緒に消す。
3. それを使っていた残りのコードを直す。
4. 自分の差分を見て、消したせいで最後の呼び手や参照を失った物（引数・変数・関数・export・import・型）を探し、それも消す。ただし公開の API には及ばない（リポジトリの中に呼び手が残らないことは、外に残らないことを示さない）。
5. **無いことを確かめる。** 消した名前ごとに、変える前の版と変えた後の木で検索する。もうどの呼び手・テスト・文書も触れていない。
6. 消した振る舞いをまだ述べている文を全部書き直す。

## 済んだと言える時

- 名指された名前とファイルを、それを縛るテストと一緒に全部消した。
- 使っていたコードを、新しい振る舞いを与えずに直した。
- 消した名前ごとの検索で、まだ触れる呼び手・テスト・文書が無い。振る舞いが本当に変わった所は、変化を示すテストを名指してある。
- 消したせいで最後の呼び手を失った物も、公開の API の手前まで消した。

## 返し方

消した名前ごとに: 変える前と後に走らせた検索と、見つかった物、一緒に消したテスト、直した残りのコード。振る舞いが本当に変わったなら、それを示すテストを名指す。

## 例

入力: 古い「表計算へ書き出す」オプションを消す、と計画が言う。

返し:

- オプションと、その処理と、処理を縛る 2 つのテストを消した。
- オプションを並べていたメニューは、それ抜きで残りを並べる。
- オプションの名で検索した: 前は 7 件、後は 0 件。どの呼び手・テスト・文書も触れていない。
- 処理の助け手は最後の呼び手を失ったので消した。オプションを述べていた利用者向けの手引きの段落を書き直した。

## 一緒に使うと良いもの

- 変更が要らなくした物を、振る舞いを変えずに片付ける見方。

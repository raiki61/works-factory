# 全部の結果を報告するテストの実行器を書く

**芯の決まり: 実行器は赤を 1 つも失ってはいけない。テストのコマンドと終了の値をそのまま保ち、テストが落ちうるどの道も報告に出す。ただし走らなかったコマンドの報告は作らない。**

## 落とし穴（先に読む）

- **渡されたテストのコマンドを 1 字も変えずに写し**、その後ろに道具に JUnit XML を書かせるオプションだけを足す。1 つのコマンドでも、`;`・`||`・パイプでつないだコマンド（`&&` も含めて混ざっていても）でも同じで、全体を 1 つのコマンドとして写し、オプションは全体の後ろに 1 回だけ足す。いちばん外側のつなぎが全部 `&&` の鎖だけは、部分ごとに書く（下）。
- **テストの道具の終了の値をそのまま返す**（どれかのテストが赤なら 0 以外）。
- **報告を書く前に赤で終わった道具は赤で、「テストが無い」ではない。** 誤りが `exit <n>` とログの在りかを言う、決まった testcase を 1 つ書く。決まった testcase は、報告を読む側がそれ用に前もって決めた classname と name（実行器を書くあなたに、テストのコマンドと一緒に渡される。実行器の引数ではないので、実行器の中に決まった値として書く）を、渡されたとおりに持つ。読む側がテストの結果と見分けられるように。
- **終了の値 126 と 127 は、コマンドが見つからない・走らせられないの意味。** その時は報告のパスに何も書かない。読み手が見るべきは「走らせられなかった」で、赤のテストではない。コマンドが道具 1 つの時、道具が書いた JUnit XML のファイルはそのまま残す。
- **形だけの本文を出さない。** JUnit XML を書かせる方法や、何を走らせるかを決められないなら、1 行で（何を読み、何が足りなかったか）そう言う。緑と決めつけない。

## 手順

「実行器の約束」はいつも読む。渡されたコマンドが「&&」だけの鎖なら「「&&」だけでつないだ鎖」を、コマンドが渡されないなら「テストのコマンドが渡されない時」を読む。

### 実行器の約束

- 対象の根（テストを回すプロジェクトのいちばん上のフォルダ）を作業のフォルダにして起こされる。
- 最初の引数は、JUnit XML を書く絶対パス。
- その後ろに引数（テストのファイル・テストの名前・絞りの式）が続いてよい。道具が受けられる時はそのまま渡す（それでテストを回すのが短く済む）。受けられないなら落として全部を回す（全部を回しても同じことを確かめる）。
- 実行器の 1 行目は `#!` の行。

### 「&&」だけでつないだ鎖

鎖全体の後ろに置いたオプションは最後の部分にしか届かず、赤の部分で後ろの部分が止まる。部分ごとに書く:

1. 各部分を変えずに写し、JUnit のオプションを足し、部分ごとに別の一時ファイルへ書かせる。
2. 前の部分が赤でも、後ろのテストの部分を回す。部分ごとの終了の値を残す。
3. JUnit のオプションを足した部分が 126 か 127 で終わったら、報告のパスに何も書かず、最初にそう終わった部分の値で終わる。
4. そうでなければ、全部の部分が回った後、全部の報告の `testsuite` 要素を 1 つの `testsuites` の根の要素の下に集めて報告のパスに書く。
5. JUnit のオプションを足したのに何も書かなかった部分は、終了の値が何でも（0 も）黙って落とさない: 集めた報告に決まった testcase を 1 回入れ（その `exit <n>` は鎖そのものが終わる値）、そういう部分の番号・終了の値・ログの在りかを全部並べる。ほかの部分の結果はそのまま残す。JUnit のオプションを足さない部分にはこれをしない。
6. テストを回さない部分（ビルドの段）が落ちたら鎖を止め、その値で終わる。126 か 127 でなければ、その部分の値・番号・ログの在りかを持つ決まった testcase を 1 回入れた報告を書く（テストが報告する前にビルドが落ちた。赤で、走らせられない実行器ではない）。
7. テストのファイルの引数は、受けられる部分だけに渡す。どれが受けられるか決められないなら、全部の部分を丸ごと回す。
8. 部分の中で最初の 0 以外の値で終わる。全部 0 なら 0（鎖そのものが返す値）。126 か 127 で終わった部分が在れば、上のとおりそれが勝つ。

### テストのコマンドが渡されない時

CI の定義と、プロジェクト自身のテストの回し方の宣言から、コマンドを決める。対象にまだテストが無いなら、対象の慣習がテストを置く所を回し、見つからなければテスト 0 件の JUnit XML を書く実行器を書いてよい。

## 済んだと言える時

- 実行器が、渡されたコマンド（か「&&」の鎖の各部分）を変えずに持ち、足したのは JUnit のオプションだけ。
- 道具の（か鎖の）終了の値で終わり、コマンドが見つからない・走らせられない時は何も書かない。
- どの赤も報告に出る: 赤で終わった、または何も書かなかった道具や部分には、決まった testcase が在る。
- 1 行目が `#!` の行。
- または、方法を決められなかった時は、本文が無く、何を読み何が足りなかったかを 1 行で言う。

## 返し方

実行器の本文か、作らなかったことと、何を読み何が足りなかったかの 1 行。コマンド・オプションの名・ファイルの名・パスはそのまま書く。

## 例

入力: テストのコマンドは `build && test-a && test-b`。テストを回すのは `test-a` と `test-b` だけ。

返し: 次の実行器——

- `build` を回す。落ちたらその値で終わり、126 か 127 でなければ、部分 1 とそのログを名指す決まった testcase を 1 つ書く。
- `test-a` と `test-b` を、それぞれ変えずに JUnit のオプションと別の一時ファイルを付けて回す。1 つ目が赤でも 2 つ目を回す。
- 2 つの報告を 1 つの根の下に集め、どちらかが何も書かなければ決まった testcase を 1 回足し、最初の 0 以外の値で終わる。

## 一緒に使うと良いもの

- 単独なら通る試験を壊す、試験の包みを直す見方。

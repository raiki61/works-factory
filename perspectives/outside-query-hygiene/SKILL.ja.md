# 外への問い合わせに対象の名前を入れない

**芯の決まり: 対象を持たないサービスへ送った問い合わせは、そのサービスの記録に残る。対象の名前も文も入れない。**

対象（渡されたリポジトリ・文書・差分）は、公開に見えても非公開かもしれない物として扱う。公開かどうかを自分で決めない。

## 落とし穴（先に読む）

- **道具は問わない。** Web の検索・Web の取得・シェルからのリクエスト・パッケージの置き場への問い合わせ、どれも問い合わせ（検索の語・URL・コマンドの引数）を外に残す。
- **どこの物か分からない名前は、持ち主の名前として扱う。** 迷ったら入れない。
- **子のエージェントはこの決まりを受け継がない。** 子のエージェントを立てるなら、この決まりを一字一句そのまま、その指示に入れる。入れないと届かない。

## 問い合わせの書き方

- 調べたい一般の問題として、数語に言い直して書く。内部のモジュールの名でなく、仕組みの一般の名で探す。
- 対象の持ち主の名前を入れない: 会社の名・製品の名・内部のコード名・リポジトリの名・ブランチの名・パス・対象自身の識別子。
- 対象の文を入れない: コードの断片・差分・文書の文。
- 第三者の名前は入れてよい: 対象の外で作られ公開された物（対象が使うオープンソースのソフト・標準・ベンダーの製品と、公開のエラー文の一般の形）。一次情報を引くのに要る。
- 対象の中だけで使う語（社内の用語）の意味を確かめる時は、その語そのものでなく、一般の言葉に言い直した定義と、標準の語の候補を探す。

## 持ち主の名前なしでは成り立たない問い合わせ

打たない。答えに「対象の名前が要るので打たなかった問い合わせ」として名指し、人の確かめに残す。答えに「足りない」「確かめられない」「見つからない（何を探したか）」の置き場が在れば、そこに書く。

## 外への問い合わせでない物

対象を既に持つ所（リポジトリ自身の版管理・リポジトリを持つホスト・そのホストのページを読む事）への問い合わせは、外への問い合わせではなく、この決まりの外。

## どの出典を使うか

- 一次情報を先に当たる: 標準の文書・公式の文書と手引き・原典・公式のリポジトリ・広く引かれる実務家の文書。
- ブログなどの二次情報より優先する。
- 古い版の話でないかを確かめる。
- 二次情報しか見つからなければ、そう書く。

# 変えた道を 1 回動かし、流れる物を見る

**芯の決まり: 動かしていない道を確かめ済みと扱わない。本番と同じように 1 回動かし、見えた値を書き留める。**

ほかのレビューのやり方は、どれも差分を読む。コードが動いて初めて現れる欠陥——動く環境に固有の振る舞い・中の層が変えた値・描画——は、差分を何度読んでも現れない。見るのは、本番と同じ道を流れた本物で、テストが緑になったことではない。

## 落とし穴（先に読む）

- **当てるのは、変更が利用者に見える道か、外との継ぎ目に触れる時。**
- **緑のテストは観測ではない。** 道を実際に通った値を書き留める。
- **「見た」には観測が 1 つ以上要る。** 動かした道と、そこで見た値が 1 つも無いのに「何か見つけた」「全部きれい」と返さない。
- **本物の作業ツリーを壊さない。** 作業ツリー・取り出している commit（HEAD）・ブランチ・版管理が無視するファイルを変えない。動かすのに要る写しは、外の新しい一時のフォルダに作る。
- **動かせない時に、動かしたふりをしない。** 環境が無い・権限が無い・本物の機器が要る時は、そう書く: なぜ動かせないかと、人が何を動かして見ればよいか。本当に手が無いかは人が決める。

## 手順

1. 変更が触る道のうち、利用者に見える物か、外との継ぎ目を通る物を見つける。
2. その道ごとに、新しい一時のフォルダの写しから、本番と同じように 1 回動かす。
3. 動かした道ごとに、実際に通った値を書き留める。
4. 動かせない道は、訳と、人が何を動かして見ればよいかを書く。

## 済んだと言える時

- 見たと返す道のどれにも、そこで見た値が付いていて、値の無い「何か見つけた」「全部きれい」が無い。
- 動かせなかった道のどれにも、訳と、人が何を動かして見ればよいかが付いている。
- 本物の作業ツリーが元のまま。

## 返し方

動かした道ごとに: 道と、そこで見た値。動かせなかったなら: 訳と、人が何を動かして見ればよいか。

ファイルの中の場所を名指す時は、差分の中の行でなく、今のファイルの行の番号を書く。差分の行はファイルの行ではなく、人がその場所を開けない。書く前にファイルを開いて行を確かめる。確かめられなければ、行の番号の代わりに、パスと関数の名などを書く。

## 例

入力: 注文の確認のページで、配達の日付を読み手の土地の書き方で出す変更。

返し: 試しの注文で確認のページを一時の写しから動かした。見えた値: 日を先に書く土地の読み手に「Delivery: 11/18/2026」——変更が日付を整えた後に、テンプレートの層がもう一度整えている。

## 一緒に使うと良いもの

- 外のサービスへの問い合わせ（Web の検索・取りに行く URL）に、見ているリポジトリ自身の名や字を入れない決まり。
